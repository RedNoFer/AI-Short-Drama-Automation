# output

适用本 skill 主入口的任务范围。以下为专科细则；用户明确选择优先。

六、输出格式

【可选：多角色差异表】
编号｜角色名｜身份｜主要廓形｜主配色｜材质要点｜识别锚点
只在多角色设计或用户要求方案时使用，不默认放品牌列。

剧本已有S03编号则沿用`@CH-001`等，不换成C001；同一角色的服装变体用版本区分。未知全身/背面补全与设计建议记录在说明中，不能当成已确认身份。

【角色 C001：姓名或称呼】
设计说明：中文，建议60-120字，概括主锚点、服装逻辑、风格和暂定项；不强制凑字。

正向提示词：默认独立代码块提供完整中文正文。用户要双语时先中文、后英文，分别完整输出；两版身份、年龄、颜色、左右位置、服装和布局必须一致，不在翻译中新增设计。
编译正文可按六个职责连续成段：主体与资产类型→身份锚点→造型/可见状态与材质→构图与画幅→光色与风格→必要限制。用户更看重版式时可把构图放到开头，主模块另有明确格式时沿用。至少写清同一身份、主锚点、关键剪裁/连接、材料表面、鞋饰、左右位置和跨视图一致性；不是把内部字段名或技能规则复制进图像输入。
无需逐一展开所有五官、皮肤纹理或身体细节。已确认特征不得在压缩时丢失。

负面提示词：仅在工具支持且任务需要时输出独立代码块。
限制应针对实际风险：额外人物、身份变化、服装不一致、视图重叠、裁切、肢体错误、文字等。
避免 multiple characters 的歧义：描述为 different identities 或 extra unrelated people，不能把设定图所需的重复视图一起禁止。
不要加入与目标风格冲突的负面词；不要残留 portrait of [any real person] 等占位符。

参数建议：代码块外说明目标工具、画幅和已核实参数；未经核实的参数不输出。

角色锁定卡：8-12个简短中文视觉短语；双语任务可附对应英文短语。优先覆盖身份、年龄段、体型、头发、面部特征、服装轮廓、主色和标志物。信息不足时可少于8项，不为凑数新增设定。固定左右侧、色彩和穿着关系，不放8K、masterpiece等质量词。

将身份不变量与当前服装版本分组，提案保持“草案/暂定”状态；确认过的主基准记录真实路径与确认依据。结构化资产交接参见[建模参考](modeling-quality.md)中的字段映射。未实际出图不写“图片验收通过”；多视图文字也不能证明已拥有可绑定3D模型。

字符统计：按语言分别列正向N＋负面M＋实际参数K＝总计T；没有实际计数工具时写“估算”，不得标为精确值。

多角色以“---”分隔；保留既有角色ID。局部修改保留角色ID并标记版本；超长批次按完整角色分批，不截断单个提示词。

七、统一字符预算

单角色每种语言的正向、负面和实际参数合计默认不超过4000个Unicode字符。双语分别检查；建议任选一种投喂，若合并使用则对合并文本重新计数。
这是本生成器的默认工作预算，不代表平台输入上限，也不约束其他模块。用户指定其他预算时采用用户预算，仍不超过实际平台限制。无需写满；平台尚未知时按默认4000执行，不编造平台上限。
计数含空格、换行、标点，不含代码围栏、设计说明、标题与锁定卡。若另将锁定卡粘贴进模型输入，需纳入那次输入的计数。

建议预算：
- 正向目标不超过2800字符；其中布局约350、身份脸发约550、衣着材质约850、配饰与衣身关系约300、风格光照一致性约550。
- 负面目标不超过700字符。
- 实际参数预留不超过100字符。
- 总目标不超过3600字符，留400字符余量。没有必要写满预算。
- 某部分确实需要更长可调配，但最终合计不超过本次采用的预算。

压缩顺序：删空泛质量词→删重复限制→删不可见工艺与传记→精简次要纹理。
保留：用户锁定项、身份锚点、视图布局、左右定位、主要服装轮廓与目标风格。
不输出“8K、相机型号、ArtStation featured”来冒充真实分辨率、摄影设备或获选记录。

八、内部交付检查

- 是否先提取已给设定，仅对关键缺项提问并等待回答，没有重复询问已知字段？
- 是否默认交付中文；双语是否中文在前且内容一致？
- 角色事实和新增提案是否分清，既有ID是否保留？
- 四视图是同一身份；三个全身同尺度，特写单独放大？
- 全身正侧背顺序、90度侧面、脚底基线、完整入画是否清楚？
- 左右锚点有无互相矛盾，服装与配饰是否跨视图一致？
- 设计强度是否适合职业、年龄、时代与画风？
- “变美/高级”是否落成具体脸发、体态、剪裁、配色或材料变量，且未改变确认身份？
- 侧面鼻唇颏、背发、后领、腰带和鞋履是否有一致的结构依据？
- 写实、CG、2D或定格是否只有一套主媒介，微纹理密度是否相称？
- 正负面有无互相抵消，是否错误禁止所需的四视图？
- 是否只有目标工具支持的参数，无占位符和伪造素材引用？
- 字符总计是否正确或明确标成估算？
- 锁定卡能否被下游直接理解，而不是只有内部编号？
- 没有实际生成图片时，是否明确交付只是提示词？
只报告会影响用户使用的问题，不把完整自检清单追加到每次回复。


## 实际计数方法
把最终正向、负面和参数分别保存为纯文本 UTF-8 文件，不含标题与代码围栏。运行：

```text
python scripts/count_prompt.py --positive positive.txt --negative negative.txt --parameters parameters.txt --limit 4000
```

以上命令从 skill 根目录运行；也可使用脚本绝对路径。没有负面或参数文件时省略对应选项。脚本只读取文件，保留换行与空格；超限退出码为1，达标为0。若合并成一个输入框，先将最终合并文本保存为单个文件后只传 --positive，这样会把分隔符一并计数。
