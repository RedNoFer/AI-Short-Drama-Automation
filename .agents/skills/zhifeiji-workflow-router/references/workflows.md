# 组合工作流与交接规范

这是路由组合规范。原始创作细节始终从 [源文件索引](resource-map.md) 对应的实际 MD 读取；S15 另读完整执行 TXT。用户只需要某一阶段时，直接进入该阶段。

## W01｜小说到多集短剧

1. [S15](resource-map.md#s15)：读取使用入口、完整指令 TXT，并按任务读取改编模式、输出类型、短剧规则。S15 的竖屏默认不覆盖用户指定的 16:9；后续镜头构图按用户画幅设计。
2. 用户要多集时建立人物/关系/时间线/伏笔档案 → 分集规划 → 按选定输出类型生成正文。拍摄稿/AI分镜读取现有剧本格式 MD。保留同一故事档案，不把每批剧本当作独立故事重写。
3. 仅当剧本有抽象心理、小说体、无法拍摄等问题，或用户要求诊断时，加 [S20](resource-map.md#s20)。已经合格不重复“治疗”。
4. 用户还要做资产：进入 [S03](resource-map.md#s03)，再按角色/场景/道具选择资产模块。
5. 用户还要视频提示词：已预设每片段时长、画幅和清晰度，且要求小墨 6.3 逐镜与 Seedance 2.5 最终正文时，转 [W14](#w14)；其他任务按目标选择 [S21](resource-map.md#s21)、[S18](resource-map.md#s18) 或 [S08](resource-map.md#s08)。

**停止点**：用户只要分集规划/剧本，不自动继续做图片或视频。
**交接**：故事档案、剧本版本、人物知情与关系变化、伏笔、服装/伤情/道具状态。
**缺项**：S15的校验脚本未附，使用人工格式检查，不报告脚本通过。

## W02｜可拍剧本到电影短片制作材料

1. 剧本已可拍则直接用；需修正才用 [S20](resource-map.md#s20)。
2. [S03](resource-map.md#s03) 拆角色/场景/道具并固定 `@CH/@SC/@PROP` 编号。
3. 用户要统一画风、参考图或色卡时用 [S11](resource-map.md#s11) 定调。传入已确定风格时不重复定调。
4. 按资产需要分支：写实人物 [S16](resource-map.md#s16)；CG/服装 [S10](resource-map.md#s10)；机械技术板 [S14](resource-map.md#s14)；一般电影场景 [S06](resource-map.md#s06)；森林荒漠遗迹定向场景 [S05](resource-map.md#s05)。不是每次都跑完这几项。
5. 空间需要补足时选 W06；已有完整多机位场景则跳过。
6. 只选择一个最终视频主格式。预设片段参数并指定小墨 6.3＋Seedance 2.5 时，执行 [W14](#w14)；其他目标按下列主格式选择：
   - Seedance 2.0完整剧本精细逐镜 → [S02](resource-map.md#s02)。
   - Seedance 2.0短片段扩写 → [S07](resource-map.md#s07)。
   - Seedance 2.5动作多镜头 → [S18](resource-map.md#s18)。
   - Seedance 2.5竖屏情绪对白 → [S21](resource-map.md#s21)。
   - Kling 3.0人物表演 → [S08](resource-map.md#s08)。

**已有分镜表**：直接继承数量、顺序、景别和运镜，不重拆整片。
**交接**：稳定资产清单、实际参考图、色卡/风格字段、镜头目的、空间位置与前后镜状态。
**产物边界**：这里可交付制作材料和提示词；实际媒体生成需要可用工具。

## W14｜预设片段的小墨 6.3 分镜到 Seedance 2.5

适用：用户在分镜前确定每条生成视频的时长规格（如 15 秒或 30 秒）、画幅（16:9 或 9:16）和清晰度（如 720p），并选定 [E24 小墨个人分镜 Skill 6.3](resource-map.md#e24) 作为逐镜导演规范。用户只给统一规格时，不必预先指定片段总数；片段边界和镜头归属在分镜规划时随剧情节拍确定。若用户已给片段边界，直接继承。每条片段可以有多个镜头，不在分镜完成后另做镜头归组。用户给出的参数优先；不要把示例值当成其他任务的默认值。

从[短剧工作流Skill](../../short-drama-workflow/SKILL.md)进入时，可由系统先根据小说、剧本和表演估时确定集数与片段规格，再执行本流程；该技能的最终视频提示词正文预算为 3000 字符以内（第二档默认；第一档 2000、第三档 4500，按 `--tier` 切换），与 S18 适配器的本地约定一致。当前单 MD 导出按[精简导入格式](../../short-drama-workflow/references/compact-import.md)保存资产图片提示词和片段绑定，不预写尚未导入的真实参考图编号；实际接口若更严，仍以接口限制为准并回到片段规划，不删关键剧情表演。

该短剧工作流目前默认每条生成片段 30 秒、6–11 镜、5–10 次明确硬切（2026-10-22 全项目统一口径）；其[项目策略](../../short-drama-workflow/policy.json)与[可机检格式](../../short-drama-workflow/references/validation-contract.md)覆盖适配器的默认时间段数量建议。每个硬切镜头在最终正文保留单独时间行，不因压缩为少量叙事段落而丢失。用户日后指定新默认值时更新策略与校验。

1. 开工前登记时长/画幅/清晰度规格。按可拍剧本的因果节拍，在分镜规划时划出片段编号与边界；每个片段明确开场事实、必须发生的事件、对白、结果和出口事实。用户已经给出逐片段边界时沿用。内容放不进指定时长时，在镜头设计前调整剧情分配并说明问题，不靠异常语速、删原句或无因加速硬塞。
2. 继承 [S03](resource-map.md#s03) 的稳定资产身份；空间不足时借鉴 [S19](resource-map.md#s19) 的场景锚点和保守补全。先做片段一致性卡：每个角色记录稳定 ID、真实参考图/已确认母版、可见身份特征（脸型、发线和发型、体态、服装版本及识别性配饰）；每个场景记录稳定 ID、真实参考图、固定地标的左右/前后关系、出入口、材质和光源方向；关键道具记录 ID、外观识别点、初始持有人与左右手。未确认的背面、脸部或隐藏空间只列为待定/提案，不写成既定事实。再记录人物的世界位置、关系轴线、移动路线和视线。S19 的环境反打不自动等于人物对话正反打。
3. 对每个预设片段读取 E24 原文并设计连续编号的逐镜分镜。执行它的物理可行性、180°轴线、视线/景别/运镜衔接、对白反应、镜头经济性和短剧视感规则。原版禁止一镜到底；仅有一两次切换的草稿默认退回重拆，除非镜头已完整承载本片段的不同信息与表演节拍；不得加无信息切镜凑数。原文的“全片/每集/每场”配额按其对应范围统筹，不对每条 15/30 秒片段重新强制凑足全片运镜种数。遵守原版优先级：物理可行性 > 叙事情绪 > 多样性指标。
4. E24 原版明确不计算时长，因此另建**已划定片段内**的镜头时间码表，给已设计镜头分配起止时间。时间码一律为整数秒（如 `0-3秒`、`3-6秒`），从 0 连续覆盖到片段终点，不得有小数、空档或重叠；同时核对对白自然发声时长、切点与动作结果。E24 原版分镜稿仍保持其仅有镜头序列的格式。时间码与片段归属随分镜完成，不在提示词阶段决定镜头如何归组。
5. 逐片段交给 [S18 的 Seedance 2.5 通用提示词生成适配器](resource-map.md#s18)：把逐镜信息整理为该片段的一条最终正文，分离画幅/时长/清晰度等生成参数；只有实际存在且本次上传的参考图才可映射图片编号。当前短剧工作流的单 MD 导出没有图片附件，【参考】只写已绑定的资产代码及可见职责，待目标应用生成并批准图片后再建立真实图片映射。公共规范只写本片段不变且**具体可见**的身份/服装版本、场景地标与光向，道具持有人、站位、动作和表情的变化写进对应时间段。单写“人物场景保持一致”不算完成一致性约束。保留台词、动作因果、主要运镜、入口与结束状态；逐镜核对原镜头编号是否在最终时间轴保留必要切点和信息职责。独立 W14 与短剧工作流按第二档 3000 字符预算（第一档 2000、第三档 4500，按 `--tier` 切换）；短剧工作流另按 5–10 次硬切规则压缩重复措辞，但**不合并已规划的硬切镜头行**。若仍超适用预算，回到第 1 步重排剧情节拍与片段边界，再重做分镜；用户已固定片段边界时不擅自增加。E24 镜头序列是中间稿，不把它和 S18 v3.5、S21 的最终模板全文并列投给模型。
6. 片段之间逐对核对出口→入口的人物位置、动作姿态、服装/伤情、道具持有、空间轴线、光源、对白与声音。原版 S18 v3.5 的尾帧承接句仅在确有可用尾帧且所用工具支持时使用；未生成或未验收的尾帧仍是文字计划，不写成实际图片引用。实际媒体生成后再验收画面、运镜、口型和声音。

**交接**：片段规格与分镜时已确定的片段编号/边界、逐镜分镜、每镜时间范围、一致性卡（稳定 ID→真实参考图→可见不变量）、片段入口/出口事实、原镜头→最终时间段/切点覆盖关系、最终 Seedance 2.5 正文及其字符数。16:9 和 9:16 应分别编排构图，720p 是生成参数，不用“高清”一词冒充实际分辨率。

## W15｜打斗路由（短剧工作流阶段 3.5）

短剧片段含打斗时的增强路由，插在小墨 6.3 分镜（W14）之后、提示词编译之前：**A 全打斗段**（完整攻防交换链）转一镜到底拍点制，打斗 skill 战斗语法优先（388 攻防五结果/受击反馈链/连招三层＋花128 二十一拍与三起两落曲线），豁免镜数带与硬切、默认按第三档 4500 字符；**B 混合段**只对交锋镜做攻防增强，其余走原规范；**C 威慑对峙**（围而不攻/只监视不攻击）跳过。画风统一不引入水墨，特效改用剧内母题；上下文衔接三接口（入镜承接/出镜收尾/跨段战损）为硬要求。判定标准、优先级裁定表、排除清单与源文件选型见 short-drama-workflow [打斗路由规范](../../short-drama-workflow/references/fight-router.md)。触发语：打斗路由、动作戏增强、这集有打斗。

## W16｜Wan3.0 提示词轨（生成模型双轨）

按生成模型选轨：Seedance 2.5 走既有 S18＋小墨规范；**Wan3.0** 走 [Wan3.0 提示词规范](../../short-drama-workflow/references/wan30-prompt-spec.md)（写法标准）与 [Wan3.0 通用提示词生成适配器 v1.0](../../short-drama-workflow/references/wan30-adapter-v1.0.md)（编译器手册，与 S18 同构）——20000 字符上限（用户目标 8000–15000，防稀释）、2–30 秒弹性时长／智能时长、0.5 秒拍点粒度、多模态参考（10 图＋5 视频作动作/运镜/特效参考＋5 音频作音色/口型驱动＋文件参考）、一致性显式枚举条款、@Image/@Video/@Audio 绑定与 `<音效>` 点标记、编辑指令整改分级。分镜层与六视角质检两轨共用；机检 `--model` 分支就绪前 Wan 轨片段人工核数。触发语：Wan3.0、万相轨、换模型写提示词。

## W17｜MiniMax H3 提示词轨（H3 结构化分支）

适用：用户指定用 MiniMax H3（海螺 H3 / minimaxh3 / H3 结构）的提示词结构。主模块：[E27 H3 提示词分支](../../minimax-h3-adapter/SKILL.md)，官方原文在 [25 minimax H3官方skill/skills/](</Users/a1/work/3000课程21个skill/25 minimax H3官方skill/skills/>)（`h3-prompt-writing/SKILL.md`＋`references/base-en.txt`＋`references/ref-en.txt`，原文不改）。触发语：minimaxh3、H3 结构、海螺 H3、Ref2VA、T2VA/I2VA/FL2VA/L2VA。

1. **判定模式**：只有文字 → T2VA；一张首帧图 → I2VA；首帧＋尾帧 → FL2VA（默认单镜头）；只有尾帧图 → L2VA；多模态全参考 → Ref2VA。官方输入上限：图 ≤9、视频 ≤3（每段 2–15 秒、总 ≤15 秒）、音频 ≤3（同上）、跨类型文件总数 ≤12。素材形态不明时按 I2VA 处理并在交付中写明所用模式。
2. **先分镜再编译**：分镜字段含镜头编号与切点（`[Shot 1]` 无时间戳，其后 `At MM:SS.mmm` 严格递增且落在时长内）、构图与景别、主体与位置、环境与光线、动作与结果、运镜（类型＋幅度＋速度写成自然英文句）、同期声、说话人 ID 与台词原文、参考标签首次出现点、入口/出口状态。分镜层可沿用 S03 稳定资产 ID、S02 精细拆镜、E24 小墨视感、S18 动作因果、E25 微表情层；**只借镜头与表演字段，最终正文必须是 H3 结构**，不并列输出 S18/S21 模板。
3. **时长口径**：片段时长**沿用目标应用的片段单位**（本项目默认 30 秒），不做额外拆条流程；正文用 H3 官方固定格式写该片段的完整时间轴。官方「Output duration: 4–15 seconds」是**模型单条输出上限**（生成侧），不是提示词字段写法限制；应用把一条拆成多条送模型时由应用分段，跨段承接登记在内部表。需要严格单条输出时，机检加 `--h3-segments official` 强制 4–15 秒并按该口径重排片段。画幅原生支持 21:9、16:9、4:3、1:1、3:4、9:16，24 FPS 原声。
4. **篇幅口径**：官方没有字符上限，官方生产 prompt 实测 2500–4540 字符／378–723 词（上游 README 的 case-T2VA/I2VA/Ref2VA）；本项目硬顶 6000 字符、低于 1200 提醒过简；Ref2VA 的 `detailed_description` 按官方 350–500 词。
5. **资产与参考标签映射**：`@CH/@SC/@PROP`（`CHAR_/LOC_`）→ `<Subject N>`；实际上传图/首帧/尾帧 → `<Picture N>`；参考视频 → `<Video N>`；参考音频 → `<Audio N>`（区分 `fully_copy` 与 `reference`）。标签一经定义全文一致。未上传的真实图片不得预写 `<Picture N>` 编号，只写资产代码与可见不变量并标注「参考图未上传」。
6. **编译正文**：base 模式＝对齐指令行（仅 I2VA/FL2VA/L2VA）＋空行＋`integrated_multimodal_description` → `overall_soundscape` → `non_diegetic_music`；Ref2VA 模式＝`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`。台词/歌词/画面可见文字保留原语言并逐字照抄，其余正文英文。
7. **机检＋人工评审**：H3 提示词正文体检跑 `python3 .agents/skills/minimax-h3-adapter/scripts/audit_h3_prompt.py <文件> --mode <模式> --duration <秒>`；交付到精简制作包时，正文原样写入 `#### 视频提示词` 块（片段时长 4–15 秒），再跑 `python3 .agents/skills/short-drama-workflow/scripts/validate_compact_package.py <精简制作包.md> --model h3`。两机检只证明格式；剧情因果、表演可拍性、空间衔接、声音来源与口型仍按 agent 独立评审，不因机检通过而放行。

**交接**：模式、成片时长与片段边界、资产 ID → `<Subject N>` 映射、实际上传素材 → `<Picture/Video/Audio N>` 映射、说话人 ID 表、每镜切点与台词归属、与既有 Seedance/Wan 轨的差异说明。

## W18｜站位图与空间真值（SCENE_JSON）

适用：多人共处、固定座位、狭小室内、站位易错或需要可计算机位的场景；短剧工作流阶段 2 建场景空间基底、阶段 3 为风险镜头出镜级增量、阶段 4 把站位编译进提示词正文。主模块：[E28 红喵导演台站位 Skill](resource-map.md#e28)。

1. **只做 JSON 与文字**。产出 SCENE_JSON 与由它编译出的自然语言站位描述。**不渲染 3D 站位图、不产出或批准写实剧照**——本目录没有红喵导演台运行时，任何"已渲染站位图/已出剧照"的表述都属伪造。E28 目录下的 PNG 仅为语义样本。
2. **风险镜头闸门**（命中才写，阶段 2 与阶段 3 共用）：多人同框 ≥2 人、固定座位或固定排位、有前后排、狭小室内、有操作位或设备承托、有人走位或离席。**单人镜与空镜不写 overlay**，不为其消耗工时。
3. **场景基底（阶段 2）**：每个命中闸门的 `@SC` 出一份 base JSON——地标与出入口、固定结构数量与左右、材质、实际光源与照射方向、角色初始位与朝向、常用机位库。坐标以地标为锚点量化（米制、+Y 向上），角色朝向用 `atan2` 对准其目标点；地标与固定结构是唯一真值，坐标只是该真值的量化表达。
4. **镜级增量（阶段 3）**：只写变化量——本镜相机 `position/target/fov`、谁进画谁在画外、`movementPath`、承托变化；不重复 `scene`/`props`/`lighting`，改为引用 base。**overlay 必须先于该镜分镜文字产出**：机位与"谁只看得到侧背"直接决定分镜怎么写，先写文字再补 overlay 等于又回到文字猜空间。
5. **六项机械校验**（可脚本化，跑 `scripts/validate_space_blocking.py`；站位继承表由 `scripts/build_blocking_table.py` 从 JSON 自动生成，含可见面、遮挡、承托与画外人物，不要手写）：①角色 `facing` 与其目标点一致 ②接地（站/跑至少一脚着地，坐姿必有椅或凳，倒地贴地）③人物与实体道具间距 ≥0.35m ④`movementPath` 不穿墙、不穿主要道具 ⑤坐姿与持物有承托面 ⑥跨镜站位继承一致（除有显式 `movementPath` 的人）。机检只证明几何自洽，"这台机位讲不讲故事"仍由 agent 评审判断。
6. **编译（阶段 4）与交叉校验**：：JSON → 自然语言站位描述，进【公共总规范】（场景拓扑、角色初始位、关系轴线、可达机位）与镜头行（相机在谁的哪一侧、朝向、看得到谁的正面或侧背、谁在画外）。**不写坐标数值、不写 `@Image`/`@图片` 编号、不写参数堆叠**——数值只留在内部档案。编译纪律与 `references/compact-import.md` 的自然语言改写对照表一致。
7. **交叉校验**：站位层与正文必须同源。阶段 5 导出时跑 `validate_compact_package.py <包> --space-dir <作品目录>/内部/04b-站位图`，查增量份数与镜头数、时间码一致、正文无坐标泄漏、画内角色已绑定、左右侧不与几何相反；不通过先修分镜或正文，不靠补"保持一致"结案。站位目录不存在时该校验自动跳过，不阻塞交付。
8. **与相邻模块的关系**：E28 是 S19（同场景正反打）的上游——先有 3D 站位真值再让 S19 补反打图；S17（多视角场景资产）出主图、E28 出站位，两者共享同一份空间事实；S03 提供 ID，E28 提供 ID 的空间实例；打斗段（阶段 3.5 A 级）的 `movementPath`、武器与相机关键帧直接来自 base+overlay。

**交接**：base 与 overlay 的 JSON 路径、风险镜头清单、站位继承表（镜对×状态维）、已裁定的机位与可见面、仍需人工裁决的物理冲突。
**停止点**：只出 JSON 与文字站位描述，不生成图片或视频。

## W19｜制作包续集（导入到已有项目）

适用：目标项目已经导入过本作品的精简制作包，现在要**追加新集（续集）**、**替换某几集**或**补写资产**。主模块：[短剧工作流 Skill](../../short-drama-workflow/SKILL.md) 的[精简制作包导入规范](../../short-drama-workflow/references/compact-import.md)「续集导入」节；续集规范原文在[在线模板](https://bowlpetdaily.com/drama-compact-package-template.md)（本地副本 `short-drama-workflow/assets/drama-compact-package-template.md` 已同步）。触发语：续集、第二季、再加几集、追加新集、导入到已有项目。

1. **先收齐材料**：上一集《精简制作包.md》（已导入项目的那份）、续集覆盖的小说原文、续集剧情目标与结尾钩子。项目决策（生成轨、片段时长、字符档、画幅）与声线母版**默认沿用上一集**，用户未提出变更时不重新确认；这些缺项不阻塞启动。
2. **对齐资产**：固定资产的**名称与代码逐字沿用上一集**；改名或加后缀会新建重复资产，基准图与连续性一起断。复用的旧资产图片提示词可留空（项目里已有提示词时以项目为准）；新增资产才写完整提示词，并保证代码不与项目已有代码冲突。
3. **只写新集代码**：续集写 E11、E12……不把旧集重复写进文件——目标应用会整集替换同代码的集，等于抹掉项目里已改好的集。上一集【收尾】的出口状态（人物站位与朝向、道具去向与持有人、场景时间与光向、情绪与未完话头、战损）是续集第一镜的入口，状态变化要有镜内可见的动作来源。
4. **沿用同一份声线母版**：`声线锁定：` 锚点逐字取上一集的母版，保证跨集同角色音色一致；母版一处修改全量重派生。
5. **续集内部照常走完整流程**：阶段 1–4（剧本、资产、分镜、提示词）不因「已有上一集」而跳过，只是入口状态直接继承上一集【收尾】，资产设计从上一集已确认的基准继续，不重做脸、不重定画风。
6. **机检加基线**：`python3 .agents/skills/short-drama-workflow/scripts/validate_compact_package.py <续集包> --sequel-baseline <上一集包>`；机检查集代码归属、资产名称对齐、代码冲突与集号接续，agent 再做一次对抗性独立评审（含跨集上下文衔接与声线一致性）。
7. **导入与后续**：导入后直接进镜头生成，不点「AI 整理」（它会按原文重新切分镜头，片段数会与文件不一致）；新集的帧计划与执行提示词需重新生成，项目锁定方案会被清空，在新集重新锁定一次。

**交接**：续集集号区间、复用的资产代码与新增资产、承接上一集【收尾】的入口事实、声线母版版本、导入后需重新锁定的集。
**停止点**：只交付续集制作包 MD；不替用户执行导入，也不声称目标应用里已有资产图。
