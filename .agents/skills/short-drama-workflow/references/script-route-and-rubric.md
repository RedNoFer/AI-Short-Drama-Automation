# 剧本体裁路线与评估基准

S15（[小说转剧本 SKILL](../../../../15%20ZHIFEIJI-小说转剧本SKILL)）是通用的竖屏短剧改编助手：多产物（bible/plan/synopsis/script/storyboard/check）、忠实/重构双模式、长篇工作流与合规条款。E26（[剧本创作 skill 合集](../../../../24%20剧本创作skill合集)）是三个**体裁专项引擎**，补 S15 没说透的硬标准。

本文件规定：**按用户要求选择体裁路线**，以及**评审时用该路线的指定标准评估**。两者是同一件事的两端——路线决定读什么、评什么。

## 一、路线定义

| 路线 | 含义 | 组合读法 | 适用 |
|---|---|---|---|
| **R-AI（默认）** | 竖屏 AI 短剧生产制式 | S15（全部）+ E26 `小说转AI影视剧本skill.md` | 目标产物是视频提示词/成片——本工作流主场景 |
| **R-SERIES** | 系列 / 季级结构 | S15（全部）+ E26 `短剧系列剧本创作skill.md` | 用户明确要系列、季、多个单元故事 |
| **R-MICRO** | 微电影（短时长精品单部） | S15（全部）+ E26 `微电影剧本创作skill.md` | 用户明确要微电影/短片质感单部作品 |
| **R-PLAIN** | 纯 S15 | S15（全部） | 用户只要通用改编与多产物，不涉体裁专项标准 |

**S15 永远是底座**：合规条款、忠实/重构双模式、故事档案与知情账、快进命令与多产物，任何路线下都保留。E26 是加法。

## 二、路线选择与反问规则（阶段 0）

1. **用户已指定体裁**（出现"系列/季/微电影/短片/竖屏短剧/AI 短剧"等明确指向）→ 直接按其指定路线，只在**该路线会显著改变工作量或产出形态**且用户表述含糊时再确认一次。
2. **用户未指定** → **在输入确认环节反问一次**（不是问卷，只一问）：
   - 问法：「本次按哪种体裁做？①AI 短剧制式（推荐，也是本工作流默认，产出可直接进入分镜与资产层）②系列季结构（多出季结构、钩子强度与余韵设计，工作量约为①的2–3倍）③微电影单部（少角色、重不可逆代价与余韵）。不指定就按①。」
   - 默认答案 ①；用户不答、超时或答"你定" → 直接按 ① 执行，**不阻塞流程**。
3. **不因以下内容反问**（沿用工作流既有原则，由系统推算）：集数、单集时长、画幅、清晰度、角色脸、服装、场景图、道具图、站位平面图。
4. 选择结果写入 `内部/00-项目输入单.md` 的**项目决策表**，字段：`体裁路线 | 依据（用户指定/推荐默认） | 路线层专属检查项 | 条件加读源文件`。

## 三、评估基准的两层结构

评审与阶段评估都按"**通用层 + 路线层**"执行，路线层只增不减、不替换。

### 通用层（所有路线恒定，永远生效）

台词逐字与说话人、人物知情边界与因果、每集目标/阻碍/升级/反转/钩子、可拍性、人物/服装/道具/空间连续性、声音来源与声线、硬规（四段结构/时间轴/硬切/字符/原文覆盖）、上下文衔接。

### 路线层（随路线切换，出处必须可查）

| 路线 | 路线层检查项 | 出处 |
|---|---|---|
| **R-AI** | ① 一个▲行＝一个可生成画面（AI 最小单位，多动作不得挤一行）② 单集体量 900–1200 字、1–3 场、20–30 个▲行、15–20 条台词（±20%）③ 爽点每集≥1、开局前 3 集必含核心爽点 ④ 心理活动必须有出口（VO/可见动作/删除）⑤ 支线宁死不留、注水零容忍 ⑥ 台词口语化短句化 ⑦ 视觉可执行性：避免大规模群战场、复杂运镜、微表情特写连续堆叠 ⑧ 每集必以钩子收尾（悬念/反转/危机/身份揭露四选一） | E26-A 九条铁律 + 格式规范 + 质检清单 |
| **R-SERIES** | ① 钩子强度每集≥L3，第 1、6 集≥L4 ② 钩子类型不连续两集重复 ③ 每 3 集释放一部分铺垫同时埋更深新悬念 ④ 人物微弧（每集）/中弧（3–4 集）/大弧（全季）⑤ 每个重要配角至少 1 集以其视角为主 ⑥ 余韵：七技法选≥3（沉默落点必选）、回望起点、每核心人物独立收束 ⑦ 反俗套审查（十大俗套突破） ⑧ 单集独立满足（单独拿出仍有情感/信息/悬疑效用） | E26-B 八条铁律 + 五级钩子手册 + 余韵设计 + 反俗套 |
| **R-MICRO** | ① 人物驱动非情节驱动 ② 核心人物 2（最多 3）、绝对禁止超 4 个有台词角色 ③ 六层人物档案，主角与对手深层需求镜像对立 ④ 情感在前逻辑在后、展示不讲述 ⑤ 代价不可逆 ⑥ 观众略领先于角色 ⑦ 每个场景都必须改变什么 ⑧ 结束在沉默中（悬置而非释放） ⑨ 反俗套审查 | E26-C 七条铁律 + 人物构建 + 余韵 + 反俗套 |
| **R-PLAIN** | 无路线层附加项（仅通用层） | — |

**优先级（写死，不得违反）**：用户当前明确要求 > 通用层 > 路线层 > 默认值与模板示例。E26-A「忠于原著的感觉，不忠于过程」只允许在**故事层**生效，**不得覆盖**通用层的台词逐字、原文覆盖与连续性要求。

### 口径适用范围（易错，必读）

R-AI 的体量口径（900–1200 字 / 1–3 场 / 20–30 个动作行 / 15–20 条台词）描述的是**竖屏短剧的单集可交付剧本**。本工作流内部 `02-逐集拍摄剧本` 是**喂给分镜的拍摄剧本层**（表演层、场次为拍摄场、不等于成片集长），两者不是同一形态：

- 内部拍摄剧本层：体量以**内容需要与分镜镜数**为准，不套 R-AI 区间；用 `--tier R-PLAIN` 机检。
- 用户可见的单集交付剧本（用户明确要求"给我每集完整剧本文本"时）：按 R-AI 区间机检，并逐条对位其制式（▲行制式、括注情绪/方式、VO/OS、群演命名、场次三行头）。
- 两者都存在时，R-AI 区间只对前者生效。

## 四、基准如何传进评审（防止评审员自选尺子）

1. 阶段 0 写定路线后，把「通用层 + 路线层检查项 + 出处」抄进 `内部/00-项目输入单.md` 的**评估基准栏**（一行即可）。
2. 阶段 1/2/3/4 的评估报告首行写明「本次评估基准：R-AI（通用层 + 路线层①–⑧）」。
3. **阶段 5 评审交接包强制携带该基准**（见 [交接包模板](handoff-template.md)）：评稿人按指定基准逐项判定，不自行选择尺子；不符所选路线基准的按严重度口径处理（体量/粒度类＝重要，钩子强度与人物弧缺失＝重要或阻断，爽点密度与反俗套＝建议）。
4. **半途换路线**必须重评：已按旧基准产出的部分按新基准重评，否则两套标准混用；换路线记录在执行账。

## 五、机检下沉

| 检查项 | 归属 | 落点 |
|---|---|---|
| 单集字数、场次数、▲/△行数、台词条数 | **脚本** | `scripts/validate_screenplay_volume.py`（按 R-AI 口径与容差判定） |
| 场序格式、闪回成对、人物名一致 | **脚本** | 同上 |
| 集尾是否有钩子 | 结构化字段（分集规划表） | agent 核对 |
| 钩子强度 L3+/类型不重复/每 3 集释放 | 人工 | 评审勾选表 |
| 人物弧、爽点密度、反俗套、配角视角、人物数上限 | 人工 | 评审 |

## 六、与其他已接模块的关系

- 与 [E25 微表情层](micro-expression-layer.md) 一致：E26-A 铁律⑦「避免微表情特写连续堆叠」与微表情层「每片段≤2 表演镜」互为佐证。
- 与 [打斗路由](fight-router.md) 一致：E26-A「避免大规模群战场」在遇到打斗段时按打斗路由处理，不受本文件限制。
- 阶段 1 的时长/集数推算口径按路线切换：R-AI 用单集体量换算片段数；R-SERIES 用季级结构与集数区间；R-MICRO 用单部时长。不可把 R-AI 的量级套到另外两条路线。
