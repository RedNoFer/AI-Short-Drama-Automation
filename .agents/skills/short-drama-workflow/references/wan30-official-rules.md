## 官方数据和本地策略

| 维度 | 官方快照 | 当前项目策略／使用边界 |
|---|---|---|
| 字符 | prompt最多20,000字符 | 制作包正文上限仍为18,000，无下限；两者差额不保证容纳全部应用附加文字，真实提交合成后再查官方上限 |
| 输出时长 | 无视频输入2–30秒整数，或智能时长-1；有视频时输入总长＋输出≤30秒 | 默认30秒只适用于既有片段规划；视频参考也占预算，不能默认再输出30秒 |
| 图片 | 参考图最多10张 | 按实际media计；角色／场景／道具代码数量仅用于内部绑定预估 |
| 视频／音频 | 各最多5份，各自合计≤15秒，单份1–15秒 | 原视频、动作、运镜、特效参考都计视频输入；两类时长分别求和 |
| 首尾帧 | 首帧／尾帧与普通参考、文件、链接互斥 | 旧版“首帧＋主体／音色”“续写＋尾帧”不能直接混传 |
| 文件／链接 | 二选一最多1份；使用时保持智能改写开启 | 链接应为可公开读取页面；不把需要登录的知识库当公开网页 |
| 输出 | 480P／720P／1080P，30fps；比例包括21:9及常见横竖比例 | 资产图画幅与视频画幅分开；示例中的8K、1000fps不是调用参数 |
| 时间轴 | 官方允许多种表达方式 | 制作包使用0.5秒逐镜时间行；不将其当成API duration可填小数的许可 |
| 结构 | 内容要素按需组合，无固定四段／七段要求 | 四段为导入容器；电商七段为另一应用模板；不能彼此替换 |
| 素材引用 | 图、视频、音频各自按实际上传顺序编号 | 离线包用代码；直接提交时才用真实槽位编号，不能凭资产代码尾数猜号 |
| 分镜与美术 | 允许固定镜头、不同媒介与情绪节奏 | 6–11镜、硬切带、指针式一致性条款、单人塑像图和禁直视镜头属于项目策略／反例经验 |

当前应用能否接受新参数、解析哪个引用标签须单独确认。官方快照更新不自动推翻用户已锁定的项目值，也不能放宽接口技术限制。

## 官方提示词要素

根据当前Prompt指南，将内容组织成：**主题与整体走向、各参考的职责、逐镜事件和摄影、逐句说话信息、声音设计、美术与情绪、必要约束**。这是要素集合，按任务取用；不因字段缺席就硬补剧情或凑字数。

编译为制作包时按以下对应：

| 要素 | 导入容器内位置 | 写作要求 |
|---|---|---|
| 主题、核心事件、情绪与节奏 | 【公共总规范】开头“总体描述：” | 一两句写清当前片段发生什么、变化到哪里，不复述全剧背景 |
| 素材职责 | 【参考】 | 离线只写真实绑定代码＝职责；未上传不能伪装已绑定官方槽位 |
| 风格、色彩、光照与身份 | 【公共总规范】 | 从已冻结母版派生；参考已锁内容不再建立另一套细节真值 |
| 每镜主体、场景、运动、美学 | 【时间轴】 | 摄影前置，动作有因果与结果；并行动作说清，实际切镜才写硬切 |
| 说话人、原话、语气、口型 | 对应时间行；声线公共定义一次 | 剧本原话不改；七类声源标签是本地验收约定，不能称官方特殊token |
| 环境、动作音、BGM | 公共声音策略＋逐镜声响事件 | 无台词、无BGM、关闭音轨分别控制；音色与节奏／原话参考分清 |
| 负向与不可变事实 | 公共层中仅保留本段适用项 | 正向动作先成立，负向不重复、不许与必要形变／光学变化冲突 |
| 当前末镜结果 | 【收尾】 | 只确认已发生状态，不新增一段动作或复制全部约束 |

独立编辑或延长指令不强制套这四段，也不要求为了过项目包机检补写一条完整30秒故事。任务分支见 [wan30-task-compiler.md](wan30-task-compiler.md)。

## 知识如何进入编写与评审

按学习文档章节定位。每镜只选有表达用途的控制项，不让九类光、十种风格或全部运镜同时挤进一个镜头。

| 当前问题 | 按需读取 | 编写时落实 | 同轮评审看什么 |
|---|---|---|---|
| 台词和声音 | 学习文档第三、八章；voice-and-dubbing.md | 触发、说话人、原句、语调／停顿、动作声时点 | 串词、嘴部状态、音色职责、对白窗口与呼吸 |
| 光线／色彩 | 第四、五章 | 光源、方向、光质、反差和主辅色分开说 | 不同光源是否有空间分工，调色是否改变身份或商品色 |
| 景别／构图／焦点 | 第六章 | 观众必须看见什么，谁在何处，焦点从哪里到哪里 | 手与道具是否可见，广角不代替景别，机位与焦距不混淆 |
| 动作／受力 | 第七章 | 初态、驱动／接触、路径、响应、结果 | 手物归属、支撑、方向、数量和可完成时间 |
| 情绪 | 第八章；micro-expression-layer.md | 触发→可见反应→声音→结束状态 | 情绪有进程，表演线索少而有效，不按标签堆脸 |
| 运镜 | 第九章 | 起点、路径、速度变化、主体关系、最终构图 | 推进／变焦、平移／摇镜、环绕／滚转、Dolly Zoom有无混写 |
| 风格 | 第十章 | 3D看比例／材质／光照；2D看线／上色／空间组织 | 多镜媒介统一；PBR等词不等于交付渲染工程 |
| 转场 | 第十一章 | 前画面、连接载体、变化过程、后画面 | 剪辑省略与连续物理过程分清，图形匹配不强迫真物变形 |
| 编辑／续写／参考 | 第十五章 | 借什么、改什么、保留什么、允许哪些联动 | 参考与当前模式相容，结尾／入口不重置 |
| 多镜叙事 | 第十六、十七章 | 目标、阻力、变化、反应与收束 | 每镜新增信息，时间轴承载得下，不凑镜数 |

有参考视频时分别说明只借动作、运镜、特效、风格还是音色。复杂组合先分阶段，不能同时要求“人物恒定大小”和“脸持续放大”；奇幻穿越明确入口、转换和落点，不能当真实摄影路径解释。

## 引用与提交前检查

1. 制作包编译先验内部绑定与冻结版本；图片未生成时只报告文字及绑定检查，不说素材已上传或图像已验收。
2. 应用提交时形成真实media清单，图／视频／音频分别重新计数，核对一份素材只承担已登记职责。应用自动追加的文字也计入最终prompt字符数。
3. 有真实请求与本地媒体信息时运行 `scripts/validate_wan30_request.py`；仅检查其声明范围。没有视频／音频时长信息不能按0秒“通过”；智能时长保留平台确认项。
4. `--media-info`使用零基media索引，例如第一个素材为视频时，信息文件可写为`{"0":{"duration_seconds":5}}`；该文件仅供本地检查，不传入API。
5. 这个请求检查器不提交、不解码媒体、不验证账号、文件字节或供应商审核，不能替代最终平台返回和成片检查。制作包仍用原包校验器，二者输入不是同一种文件。

```bash
python3 .agents/skills/short-drama-workflow/scripts/validate_wan30_request.py 请求.json --media-info 媒体信息.json
```

如额外核对制作包18,000字符，添加`--package`；这只加查字符，不把API请求当成制作包MD。

## 维护方法

- 官方变动：修改机器快照、核对日期与对应说明；有明确数值／组合变化时同步请求检查回归。
- 用户项目值变动：修改policy与引用，保留官方快照，不把18,000替换成20,000后覆盖所有存量项目。
- 新的生成反例：按既有案例规则留证、限定适用范围。一次样片失败不能改写官方支持范围，也不能把照片排版、慢镜或暖光一概称为模型不支持。
- 不新增一轮重复语义评审；把本表检查接入现有阶段4全覆盖评审和变更后定向复验。
