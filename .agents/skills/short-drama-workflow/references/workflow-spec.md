# 最新工作流规范（v3｜2026-10-26）

> 本文件是阶段、产物、门与模型分支的**唯一总览**。具体写作规则仍以各阶段 reference 为准；模型差异见 [生成模型分支矩阵](model-branch-matrix.md)。

## 0. 一条主线，三种模型 profile

本项目只有**一条从小说到精简制作包的主线**，不是三套工作流。阶段 0–3.5 的剧情、资产身份、连续性合同、空间、分镜语法与评审视角三轨共用；只有阶段 3 的片段形态、阶段 3.5 的 A 级镜头长度、阶段 4 的编译器、阶段 5 的校验器/字符档和评审硬规附录按模型切换。

- 一个项目在阶段 0 必须登记**一个且只有一个最终生成轨**：`seedance25`｜`wan30`｜`h3`。用户明确指定的分支优先；轨道缺失、无效、重复或与校验命令不一致时，阶段 4/5 失败关闭，不得静默回退到 Seedance。
- 同一项目不得把 Seedance 四段、Wan 四段、H3 base/Ref2VA 混写进同一个片段。
- `Seedance 2.0` 是**独立路由族**：S02 完整剧本精细逐镜、S07 15 秒短片段、S13 角度运镜；它不是本 30 秒多镜主线里的 `seedance25` profile。若要把 2.0 做成第三条完整分支，必须另建 `seedance20` 适配器与校验器，明确片段单位、字符上限、参考语法和包结构，不能直接套用 Seedance 2.5 的 S18 四段与 2000/3000/4500 档。

## 2. 阶段 3 的分支差异

阶段 3 的**叙事/分镜语法共用**，但片段形态按轨切换：

| 轨 | 默认片段 | 镜头/硬切 | 时间粒度 | 备注 |
|---|---|---|---|---|
| Seedance 2.5 | 30 秒 | 6–11 镜 / 5–10 切 | 整数秒 | **Seedance 分支内**第二档 3000 字符为默认；第一档 2000、第三档 4500 试点。不得作为通用默认或用于 Wan/H3 |
| Wan3.0 | 30 秒默认；允许 2–30 秒弹性 | 6–11 镜 / 5–10 切为默认；按用户/项目策略可改 | 0.5 秒 | 仅 18000 字符硬上限，无字数下限或目标带；参考图/视频/音频有数量上限 |
| MiniMax H3 | 30 秒应用片段默认；官方单条 4–15 秒 | 0–6 切；FL2VA 默认单镜 | 毫秒切点 | **默认不额外拆条**；只有应用只接受单条输出才用 `--h3-segments official` 强制 4–15 秒 |

H3 的「4–15 秒」是**模型单条输出上限**，不是制作包片段的默认长度。阶段 3 不得因为看到 4–15 秒就把所有 H3 项目重新切成 15 秒条；这是当前规范已修正的冲突点。

## 3. 连续性合同（与模型无关）

分镜阶段把确定的入口/出口事实登记到 `内部/04c-衔接事实.json`，格式唯一为 `continuity-facts/2`。逐镜剧情和表演仍写在04分镜表；此文件只登记供跨段核对的事实，不能替代逐镜评审。

| 字段 | 必需内容 |
|---|---|
| `schema` | `continuity-facts/2`；旧版须补齐事实后重新验收，不沿用旧通过结论 |
| `upstream` | 冻结总分镜表的 `file`、`sha256`，必须与当前文件一致 |
| `segments[].id / next` | 规范ID如 `E01-SH01`；按源文件顺序指向相邻片段，最后一段为 `null`，不许跳过接口 |
| `shots` | 每镜 `no/start/end`，与分镜及最终正文时间轴一致 |
| `entry / exit` | 场景 `location`、时间 `time_of_day`、光向/照明状态 `light`；均须具体，不留TODO |
| `characters` | 入口/出口各列对象 `code/pos/face/costume/injury`；没有人物明确写 `[]`，无伤写「无伤」 |
| `props` | 入口/出口各列对象 `code/state`；状态写清所在位置、持有人和开合；没有道具明确写 `[]` |
| `transition` | 位于**接入段**，省略时按 `continuous`；有意转场用 `cut/time_jump/flashback/dream/supernatural`，必须有 `reason/evidence` |
| `handoff_changes` | 位于**接入段**，登记与上段出口相比的变化，每项 `kind/code/evidence`。kind为 `arrival/departure/prop/position/costume/injury/light`；人物或道具填资产代码，照明用 `code: "scene"` |

例如上段出口仍持碗、下段入口已放下，不能静默删除道具：若已在上段镜内完成放下，应先修正上段出口；若交接处确有动作，接入段用 `handoff_changes` 登记 `prop` 及对应分镜证据。角色离画、转向、换装同理。合法闪回可改变场景、人物与服装，但须有转场理由和依据。脚本验证登记、同源时间轴、绑定和接口闭合；独立评审核实证据是否真实支持变化。

**门与版本锁**：阶段3门在提示词开工前对冻结总分镜表强制核对完整事实；阶段4门再对最终正文交叉核对。缺文件、字段未填、漏段、跳过相邻接口、未声明的状态变化或分镜哈希过期均阻断。事实文件纳入阶段门收据；提示词批次锁本批和相邻接口事实哈希，无关片段变化不使本批结论失效。风险站位豁免不豁免连续性事实。

`--init` 只派生待填骨架，不代表验收通过；默认不覆盖已有事实文件。批次可用 `--facts` 指定隔离文件，阶段3全局门前合并为唯一完整04c文件。人工更新事实后，先核对所引分镜，再登记当前分镜哈希，不能仅刷新哈希掩盖内容过期。台词、潜台词、表演节拍与镜头美学由剧本/分镜决定，不以增添无关动作来满足连续性检查。

## 4. 分阶段验收与提示词评审

1. **阶段 0 输入门**：总控核对项目输入、原文范围、体裁路线、唯一生成轨和相关参数；字段齐全后冻结输入版本。
2. **阶段 1 剧情评审**：事件/分集、逐集剧本、片段规划三个交接点分别评审，落 `01c-剧情评审.md`。每次评审聚焦本交接点新增内容与受影响事实，不要求重复重审已通过且未变部分；无通过记录不得进阶段 2。
3. **阶段 2 资产评审**：隔离评稿人核对身份、美工账、声线、持物链和空间基底，落 `03b-资产评审.md`；阶段 2 门强制，并回查阶段 1 三项通过证据。资产与声线文字母版按用户已有约束标「工作流定版 vN」；仅明确要求审批或已有待决偏好时等待用户，真实试听与声源冻结不阻断 MD 交付。
4. **阶段 3/3.5 分镜与打斗验收**：按片段批次由独立评审核对动作时长、镜头与站位可行性、上下文衔接、视感和打斗路由证据；路由与分镜同步登记、复核，合并后做一次全局交叉检查，依次运行阶段 3、3.5 门。动作时长或空间几何问题应在此阶段解决，不留给提示词阶段。
5. **阶段 4 提示词评审**：全部提示词按已冻结上游编译完成后，做一轮独立全覆盖评审，落 `05-提示词评审与整改.md`（或分拆＋索引）。评审检查提示词是否忠实、清楚、可执行地呈现通过稿，以及模型分支规范、资产引用、声音和段间衔接；不重新创作或常规复审已通过的剧情、资产与分镜。修复时未变提示词凭独立内容哈希确认；变更提示词、相邻接口和受影响共享项复核。报告分节、共享依赖和批次范围锁按[多智能体评审契约](multi-agent-execution.md#阶段-4-评审报告与范围版本锁)；阶段4门同时检查全局总评和未关闭缺陷。
6. **阶段 5 导出机检**：只验证最终包结构、分支硬规、绑定、原文覆盖、空间交叉和清单完整性。复跑机检是导出安全检查，不触发对未变内容的第二轮语义评审；错误定位到具体提示词或字段后，只修该项及其依赖。

评审是**判断层**，不是事实层。人物位置、场景/时间/光向、服装/道具/伤痕、动作时长、绑定/参考编号等确定性事实应在其所属上游阶段写入合同并检查通过，再供提示词使用。提示词评审核对其是否正确继承这些事实；若发现源稿本身有缺陷，登记为上游漏检，只退回最早出错的具体产物及其下游依赖，不重启阶段 0–4。

## 5. 门与「完成」的定义

- 阶段 1 凭三个交接点评审放行；阶段 2、3、3.5、4 落盘后跑对应 `validate_stage_artifacts.py` 门（3.5 登记与复核随阶段 3 同步，合并后依次跑 3、3.5 门）；`--stage all` 0 错才可交付。
- 交付前另跑 `validate_workflow_manifest.py <作品目录> --strict`：核对生成轨、`01c-剧情评审.md`、`05`/`05-评审索引.md`、`06-机检结果.txt` 的 `--model`、执行账与唯一非备份包。阶段 1/4 的评审内容门以它为准；缺项先回补或按 legacy 登记，不得直接写通过。
- 最终交付只能有一个非备份 `精简制作包*.md`；备份、内部评审、分镜表不进入交付。
- 未实际生成视频，不得写「遵循提示词验收通过」；只能写「提示词/包机检与评审通过」。
- 残余必须登记；不得用「0 警告」或「全部通过」掩盖未清零项。
