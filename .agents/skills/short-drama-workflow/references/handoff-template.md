# 交接包实例模板（总控 → 子任务）

[多智能体隔离执行](multi-agent-execution.md)的填空式交接包。新项目每个阶段首单直接复制对应模板，花括号由总控填写。规则：给路径不给全文；白名单外文件执行员不得读取；执行员只写「产出」列出的文件。

## 阶段评审统一放行字段

评审记录用明确字段供总控和派单脚本读取，结论只能填 `通过` 或 `需修改`；“建议”“基本通过”等文字不作为放行状态。

- 阶段 1 的 `01c-剧情评审.md` 分别给出 `事件/分集`、`逐集剧本`、`片段规划` 三个标题和各自的 `结论：通过`；文件末尾写 `未关闭阻断/重要缺陷：0` 与独立评审人标识。
- 阶段 2 的 `03b-资产评审.md` 写 `结论：通过`、`未关闭阻断/重要缺陷：0`、独立评审人标识。
- 阶段 3 的每份批次评审报告写 `分镜批次复核结论：通过`、`打斗路由复核结论：通过`、`未关闭阻断/重要缺陷：0`、被评草稿 SHA-256 和评审人标识。
- 阶段 4 的全覆盖评审写 `结论：通过`、逐条片段 ID 与最终包正文哈希、`未关闭阻断/重要缺陷：0` 和独立评审人标识；哈希必须对应当前包内 `#### 视频提示词` 的 `text` 块正文。

> **阶段 3 / 4 的卡不再手填（2026-10-25）**：这两张卡里的唯一模型轨、字符档、硬切带、上游 SHA-256、校验命令一律由 `scripts/build_handoff.py --stage 3|4 --batch <范围> --out <卡> --manifest-out <manifest>` 生成，本文件对应段落只作**字段参照与话术范本**。手改卡内数值视为违规派单；发现卡与 manifest 不一致，回总控重新生成，不就地修补。

## 阶段 2 资产评审员交接包（隔离评稿人，不读下游）

```text
【阶段】2 资产母版独立评审（范围：{角色/场景/道具全集}）
【被审产物】内部/03-资产与空间设计.md；内部/04b-站位图/SCENE_LOC_*.json（命中风险闸门时）
【对照依据】references/prompt-layering.md（资产图写什么/不写什么）；references/asset-image-production.md（九块字段与阶段 2 出口条件）；references/voice-and-dubbing.md；references/outfit-variants.md；failure-cases.md#character-01、#layer-01、#proc-04
【六个对抗视角】
① 身份锚点：脸型骨相、眉眼鼻唇相对关系在正/侧/背三视图是否都成立（正面与侧面须是同一条连续轮廓）
② 妆造与饰件：素颜、无饰品是否显式写明；发饰固定位置能否接上背面
③ 服装与变体：服装三层是否可辨；命中换装条件是否登记为 PROP 变体并写归属
④ 声线母版：每发声角色 3–5 锚点、角色间反差、旁白/混叠/低语定义、声源方案；文字锚点能否清楚区分角色（真实盲听留待媒体生成验收，不声称已试听）
⑤ 持物链：每道具一行（获取点→持有人变更→去向），是否存在「早于获取点出现」
⑥ 分层与去重：资产图是否写全外观/空间/形制，是否混入镜头/台词/表演/剧情动作/多状态；同一事实是否在两个资产里重复（R31）
【产出】内部/03b-资产评审.md：逐项结论＋证据（引用资产提示词原句）＋缺陷（位置/预期/现状/严重度/退回阶段）；**必须含「分层与去重」段**。报告末尾固定写 `结论：通过/需修改`、`未关闭阻断/重要缺陷：N`、`评稿人：子任务 ID/模型`；只有结论通过且 N=0 才能放行。
【禁止】不改文件；不读阶段 3/4/5 产物；不接受「执行员自检通过」作为证据；不接受一句「通过」结案
【返回】结论(通过/需修改)、缺陷清单、评稿人标识（子任务 ID/模型）
```

## 阶段 3 执行员交接包（分镜，按集派单）

```text
【阶段】3 片段与分镜（本批：{E0X SH01–SH0n}）
【批次与版本锁】批次ID：{ID}；主剧本/资产/空间基底哈希：{SHA-256}；本批范围与相邻边界：{明确列出}
【必读】references/story-evaluation.md；references/content-expression.md（保留剧情事实的敏感内容表现）；小墨6.3原版全文；W14 组合流程；动作戏加读 S18 v3.5
【上游输入】
- 内部/02 本集剧本段落；内部/03（资产 ID、空间卡、声线母版压缩版）
- 上一集末片段【收尾】与出口事实（站位/道具/光向/情绪）；本集下一集首镜入口事实
【产出】内部/派单/{唯一批次名}_分镜.md 与专属 overlay 目录；主 `04-片段规划与逐镜表.md` 只由总控在本批独立复核后合并
【依据原句】本条派单里每个事实约束的正文出处（逐字原句＋集/片段/镜头）；给不出原句的约束不得下派

【闸口】① 镜数、切数与时长按登记轨：Seedance/Wan 默认30秒、6–11镜/5–10切；H3 默认应用片段30秒、0–6切；打斗A段按本轨豁免；时间轴连续（Seedance整数秒、Wan 0.5秒、H3毫秒） ② 上下镜与跨片段衔接闭合 ③ 台词逐字且时间容纳自然语速 ④ SPACE/SYNC 按反例核对、风险镜overlay与镜表一致 ⑤ 每镜E24可执行 ⑥ **本批视感统计与逐镜表一致**（`crosscheck_storyboard.py`）⑦ 独立评审记录引用本批哈希；由总控合并后再跑全局出口门 `--stage 3`；⑧ 打斗路由A/B/C随本批分镜同步落盘并复核；阶段3、3.5门均为0错误才解锁阶段4
【禁止】不写最终视频提示词正文；不为凑切镜加无信息镜头
【返回】结论/证据路径/片段与镜头统计/未决衔接点
```

## 阶段 3 独立评审员交接包

评审员与执行员隔离，只核对本批冻结的剧本、资产/空间事实、镜头表与站位增量。对照可执行时长、机位/站位、道具承接、台词时间、上下镜连续性、视感统计、打斗路由与原文证据；不得重写分镜。报告末尾按统一字段给出结论、未关闭缺陷数、被评草稿 SHA-256 和评审人标识。只有结论为通过、缺陷数为 0 且批次门为 0 错误，批次才可标记通过。

阶段3的同轮独立评审还须按 [references/content-expression.md](content-expression.md) 核对需适配镜头的剧情事实、含蓄表现与观众接收依据；通过后才冻结该版本，不把表达问题常规留到阶段4重做。

## 阶段 4 执行员交接包（视频提示词编译，按片段批次派单）

```text
【阶段】4 最终提示词（本批：{片段ID范围}；批大小按多智能体执行规范的分轨建议）
【唯一生成轨】从内部/00-项目输入单.md逐字抄录：{seedance25|wan30|h3}；只用该轨适配器、格式和校验器；Wan/H3 禁止传 `--tier`
【批次与版本锁】批次ID：{ID}；输入单/资产/声线/全局分镜冻结哈希：{SHA-256}；全局 `--stage 3` 与 `--stage 3.5` 已通过的记录路径：{路径}
【必读】references/prompt-layering.md；references/prompt-review.md；references/content-expression.md；references/voice-and-dubbing.md；references/compact-import.md；
按唯一生成轨三选一：Seedance 2.5＝S18 适配器 v1.0；Wan3.0＝references/wan30-prompt-spec.md＋references/wan30-adapter-v1.0.md；H3＝H3 专项分支与官方结构
【上游输入】内部/04 本集逐镜表；内部/03（声线母版压缩版逐字可用、公共母版、资产职责）；
上下游片段出入口事实；本集小说原文（逐字）；命中站位风险的片段须由 `build_handoff.py` 仅列本批匹配的 `04b-站位图/SCENE_LOC_*.json` 基底和镜级增量，作为空间合同核对依据；不得扫描整个目录，最终提示词只写自然语言站位、不写坐标
【产出】内部/派单/{唯一批次名}_提示词草稿.md（每段完整标题、绑定与提示词）；每段 lint 和批次机械检查通过后，总控即可合并到符合固定模板的唯一 `精简制作包.md` 待评稿（含资产图片提示词、小说原文、绑定和提示词）。该状态仍为「待评」，不等待批次语义评审。
【闸口（写每条时即时自检）】
① 先从输入单核对生成轨，并核对正文模板：Seedance 用【参考】【公共总规范】【时间轴】【收尾】；Wan 用 Wan 三模块与 0.5 秒时间粒度；H3 用官方 base/Ref2VA 字段。无【参数】
② 时间轴、切点和片段时长按本轨策略连续覆盖；不得把另一轨的时间粒度或切数套入；镜头编号只存内部04表，正文不出现 `｜镜头…｜起始/硬切｜`
③ 七类声音标签+「口型」；台词逐字；声线锁定行只列本片段实际发声者且逐字取母版
④ 表演层：按 micro-expression-layer.md 把表演原型落成可见生理线索（每镜≤2个、片段≤4个、正常速度动词、非笑点剧情避用微笑歧义词）
⑤ 字符口径按轨：Seedance 2.5 按明确登记的 `--tier`（2000/3000/4500）；Wan3.0 仅硬上限 18000 字符，无字数下限、目标带或单拍字数配额。H3 硬顶 6000、低于 1200 提醒。Wan/H3 不传 `--tier`。报告每条实际 Unicode 字符数
⑥ 分层与去重：角色只写三锚（发型／固定饰件／外套品类＋固有色），场景只写机位/朝向/光位/可走位置/出入口，道具只写状态；资产图已锁的脸、服装剪裁材质、建筑结构材质、道具尺寸纹样没有在正文重写；场景空镜，人物/车辆均有绑定（R31）
⑦ 写作期间逐段运行 `lint_segment.py`；批次落盘后可将批次包送入 `validate_compact_package.py <批次包> --model {branch}` 做机械检查，只在 Seedance 上追加 `--tier`，Wan3.0 另运行 `audit_wan30_antipatterns.py --strict`。此时批次状态保持「待评」，不派独立语义评审。所有批次完成并合并后，先跑完整提示词集的分支包校验与原文覆盖率；机检清零后由总控派发一次阶段 4 全覆盖提示词评审。
【禁止】不预写 @Image；不改台词；不临场改音色；不删剧情凑长度
【返回】结论/每条Unicode字符数/引用资产清单/本批SHA-256/校验命令与结果/未决问题
```

## 阶段 4 全套提示词独立评审（全部草稿完成后）

```text
【阶段】4 全集提示词独立评审
【范围】按固定模板组装的 `精简制作包.md` 待评稿中的全部提示词；可由多名评审员按互不重叠的片段范围分工，总控检查跨范围接口与总覆盖。分拆报告数量不限，`05-评审索引.md` 逐文件列出实际报告名；各范围不得重叠且须覆盖全集，仅索引列出的报告参与验收
【必读】最终提示词草稿；内部/02、内部/03、内部/04、04b站位与打斗记录；references/prompt-layering.md；references/prompt-review.md；references/content-expression.md；本轨适配器与分支规范；输入单指定的评估基准
【版本锁】上游冻结哈希；完整提示词集机检与原文覆盖率通过记录；逐条片段 ID 与提示词正文 SHA-256 清单
【视角】①剧情忠实与因果 ②提示词落实表演、语速、动作结果与战损承接 ③对照已通过的空间/上下文合同核对站位、视线、道具与光向 ④声音来源、口型与声线锁定 ⑤已批准分镜视感/打斗路由是否被忠实编译 ⑥所选分支硬规、字符档与参考图约束 ⑦提示词分层、角色锚词一致和去重
【边界】评审提示词是否忠实、清楚、可执行地编译冻结上游；不常规重做剧情、资产、动作可行性或空间设计。源稿缺陷登记为「上游验收漏项」，退回最早出错阶段。
【要求】每条提示词覆盖并引用正文与对应源稿证据；阶段 3 的动作时长、几何站位和分镜视感不在此重新设计
【返回】实际报告按「## 片段 E01-SH01」分节，每段写本段证据、缺陷/修复记录及唯一的当前验收表行（片段ID｜正文SHA-256｜结论）；片段ID与当前包正文哈希逐条相等且结论明确为「通过」。重复行、冲突、待评或需修改均阻断；历史缺陷记录不复制当前验收表。片段外记录独立评审人、冻结上游及共享约束；末尾「## 全局汇总」写「结论：通过/需修改」「未关闭阻断/重要缺陷：N」，仅结论通过且 N=0 放行。哈希口径与范围版本锁见 multi-agent-execution.md「阶段 4 评审报告与范围版本锁」。台账 --review 绑定实际报告，不绑定仅列链接的索引。
【修复复验】只更新并复验变更片段分节、相邻接口及受影响共享依赖；其他片段评审更新不作废本批。共享约束或评审人变化仍使依赖批次失效；全局汇总单独由阶段4门检查。旧平铺报告保留整文件锁，不伪造既有通过结论
```
