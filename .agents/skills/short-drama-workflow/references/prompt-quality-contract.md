# 提示词质量与交付闭环（完全体／Wan 快速档共用）

本文件定义本轮整改的写作与验收口径；其他文件引用本文件，不另立字数质量目标。格式、时长和长度上限仍按项目登记的模型分支执行；Wan 本项目硬顶 18000 Unicode 字符，无长度下限。字符数只记录容量，不能证明表达质量。

## 1. 逐镜质量：有职责、有表达、可执行

逐镜检查以下六项，按本镜职责给出判断；确不适用时说明原因，不为填字段编造动作。机位、光线、动作、表演和声音是可选的表达手段，不要求逐镜平均展开，不设逐镜或平均行长目标。

| 项目 | 验收问题 | 缺口修复 |
|---|---|---|
| 叙事职责 | 观众获得什么信息、情绪或关系变化？ | 明确镜头用途及必要内容 |
| 动作与状态 | 对象、方向、必要接触、受力与结果是否清楚？ | 补影响因果或后续镜头的过程 |
| 画面可见性 | 景别、机位、焦点和遮挡能否呈现重点？ | 修构图；背影／剪影不能同时要求观众看清瞳孔 |
| 时间容量 | 台词、动作、停顿哪些先后、哪些并行，能否放进镜长？ | 调整动作、时长或切点；单纯词数估时不等于试配 |
| 连续与一致 | 人物、持物、服装、伤情及入口出口是否相容？ | 修事实来源和状态承接 |
| 视听表达 | 表演、运镜、光影、声音是否帮助表达？ | 保留有作用的细节，删除同义复述及干扰 |

新增细节应服务信息识别、动作理解、情绪、空间或有意的视听效果。复杂动作和关键反应可以详写；反应延迟、动作中断、声音落点等应落实为可见可闻行为，不靠抽象情绪词或装饰性细节扩字。不因短判错，也不因长判详细。

写作流程：明确表达重点 → 写镜头 → 核容量、可见性与冲突 → 当段机检 → 全包语义合评。首遍尽量写足，发现具体缺口允许定向改写；不设为加字而进行的增密工序，也不以编辑次数或工时预算截断必需修复。

## 2. 字段职责与唯一来源

- 【参考】一次声明图像职责。默认装：`CHAR_01＝身份与默认着装基准`。整套换装：`CHAR_01＝身份基准（脸、发型、体态）`；`PROP_14＝本段整套着装唯一基准，由 CHAR_01 穿着，替换人物图默认着装`。局部单品明确覆盖部位，其余沿用默认装。镜内换装另写时间及动作；回忆／幻象造型切换应明确各镜适用来源，不伪造现场换衣动作。
- 不再强制独立【角色一致性】和公共层“着装来源”重复指针；不要输出“本文只写……”等写作者说明。旧包可兼容读取，但新稿不得复制重复段。绑定、有效身份职责、服装归属／覆盖关系和声线仍须检查。服装颜色、款式、材质由资产图承担；镜头只写必要接触和剧情状态变化。
- 【公共总规范】只放全段适用的风格、空间入口及声音规则；题材／视觉母版按角色、场景、道具职责转写，不把所有道具强加超自然符号，不跨项目复制画风基线。
- `禁止项：`独立一行，只列本段适用的生成缺陷。人物名单、数量、血珠、遮挡、构图和背景填充等正向画面设计，放空间入口或对应镜头；仅某镜成立的事实不得写成全段要求。单框正文中的禁止项不是平台独立负向通道。
- 公共事实定义一次，镜头行描述本镜变化；关键状态可在收尾简述核对，但不得新增动作或推演下一段。

## 3. 资产实例与连续性

在既有资产／节拍记录中按需登记：物件实例、参考资产代码、状态、持有人／位置、整体与局部关系。一个实例可以有多张状态图，同一张通用图也可以服务多个明确区分的实例。

核对：同一契约的展开／收拢态；普通伞与监视者伞为不同实例；挂链特写是已有部件的局部参考而非新增链；两个杯子分别归属，裂纹只落在指定实例。不要用新增资产图代替动作交代。

对关键变化核对“入口状态 → 动作或合理省略 → 出口状态”，覆盖镜内、相邻镜头和片段接口。例：保温箱合盖 → 打开取袋再合盖 → 血袋在手、箱仍在脚边；纸巾被手帕替换时交代接替。允许可理解的省略及时间跳跃，不要求拍全日常操作。瞬态不强制全态建卡；稳定复用的形态或关键证据需要参考时才建变体。

## 4. 原文、剧本与镜头的事件对照

在既有节拍表登记关键事件的来源位置、对应镜头、保留／合并／移位／省略及理由。覆盖时间跳转、动机、关键证据、关系变化、结果和集末钩子。另对照锁定台词逐字核查，差异按项目改编授权裁定，登记差异不等于获得授权。

`validate_novel_coverage.py`只验证“小说原文”摘录块对已登记源文的文字覆盖，不验证剧本或视频提示词的剧情覆盖。源范围须从已登记原文件截取并可追溯，禁止反向复制包内摘录制造满分。不得用覆盖率、镜数或绑定通过替代语义结论。

## 5. 合评证据与最终版本

快速档在一份 `内部/验收记录.json` 保存轻量记录，不恢复完全体多份审稿档案；完全体沿用原有逐项证据 JSON。记录须覆盖实际交付片段，包含：

- 最终包 SHA-256、源文／剧本及当前节拍和资产依据的路径与版本；机械检查命令、结果及未执行项。
- 每片段的关键源事件／对应镜头、六项质量判断、实例／状态及相邻接口的具体依据；引用能定位的原句或镜号，不写全包一行“通过”。
- 缺陷、实际修订和复核依据；记录作者／评审执行者，未独立评审时如实标明作者自查，不能虚构独立身份。
- 文字包、实际参考图、真实提交文本和成片分别标状态；无图／无视频记待核验，文字通过不推断成片通过。

修改正文后旧验收不再代表新版；改共享资产复核使用片段，改出口复核相邻入口，改剧情／台词复核事件及容量。未变项可保留有版本依据的结论。完成实际复核后才更新指纹，不得只换哈希刷新通过。导出后对最终文件重跑登记轨机械检查，未关闭内容缺陷不能宣布交付通过。

快速档最终导出命令：`python3 .agents/skills/fast-drama-workflow/scripts/fast_gate.py <包> --novel <已登记源范围> --delivery`。普通命令仅作写作期机械预检；`--delivery` 增加轻量记录的版本、片段范围及引文存在性检查，不能自动证明语义判断正确。

记录字段（不是通过记录模板，不得原样填写示例判断）：

- 顶层 `package_sha256` 为最终 MD 字节指纹；`review_mode` 为 `author_self_check` 或 `independent_review`，`reviewer` 如实标执行者；独立评审还须登记与 reviewer 不同的 `author`。`media_status` 的 `references/submission/video` 分别记录参考图、真实提交与成片状态：`pending/checked/failed`；机器不推断媒体合格，实际核验依据保存在原记录中。
- `inputs` 列表逐项为 `{"file":"相对作品目录的依据路径","sha256":"本次实际依据的字节指纹"}`；包括本次源文／剧本、节拍、资产和站位等实际依赖，缺项由评审核查。机器核对已列文件存在且版本未变。
- `segments` 逐段包含 `episode`、`shot`、`status`（内容问题关闭后才填 `pass`）、`source_file`（来自 inputs）、`source_quote`（准确源文引文）、`event_mapping`（关键源事件→本段镜头及取舍），以及 `prompt_quote`（准确提示词引文）、`state_interfaces`（实例状态与接口判断）。单条源引文用于版本定位，不能替代本段全部关键事件对照。
- 每项 `quality` 为对象，`purpose/action_state/visibility/capacity/continuity/expression` 六键分别填写具体判断；不适用也说明原因。`defects` 为缺陷数组，无发现时为 `[]`，关闭项含 `status: closed` 和具体 `resolution`；机器拒绝未关闭项。不得批量填空泛通过来伪造审查。

## 6. 拆段与导出

2026-11-12 用户批准：Wan 片段默认单场景；为保留已批准的剧集时长和叙事尾钩，可在项目输入单登记逐镜双场景方案。每镜声明唯一已绑定场景锚，场景切换明确硬切及新入口，参考职责限定适用镜头；绑定行不混入时间／备注。SCENE-MAP 机检验证引用和切换标记，语义合评核对两地人物、道具实例及光位，不能把两套空间混成一个地点。

按已登记入口能力与用户规格决定是否拆段，不因文本长擅自改变固定 30 秒项目规格。需要改变规格时先更新规划和验收依据；单纯拆段工作稿明确标为非正式提交稿。

正式拆分单元必须重新编译参考集合、总体描述、入口、出口、声线、造型范围及相对时间，不能只截取时间轴后复制整段上下文。内部保留父片段与镜头映射；每个提交单元可独立使用，无无关候选资产和先前入口。暂存草稿冻结后装配交付包；交付后修订以当前正式包为基线，旧草稿标历史或重新派生，禁止旧草稿覆盖新包。

代表性样片可验证新画风、多人互动、换装和动作遵循，但实际生成须在授权范围内进行。未生成时只交付文字验收结果与待验证项，不以样例文字或脚本测试冒充成片实证。
