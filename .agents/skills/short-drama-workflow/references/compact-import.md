# 单文件「精简制作包」导出规范

目标导入模板固定为[在线原件](https://bowlpetdaily.com/drama-compact-package-template.md)，目录内有[本地副本](../assets/drama-compact-package-template.md)。用户无需每次提供路径。使用该模板时，用户最终只收到一个 `精简制作包.md`；下述剧本推算、资产设计、分镜、连续性卡和评审仍在内部完成，不向导入文件追加解析器不识别的章节。

## 唯一可导入的文件结构

保留模板的标题层级、字段名、`text` 代码块和全角 `｜`。顶层先写 `# 精简制作包`、`## 固定资产`，再按顺序写各集。不可加入自定义标题、表格、说明段或整个文件外层代码块。模板中的说明注释和占位文字在成品中删除。

1. 每项固定资产写 `### 角色 CHAR_01｜姓名`、`### 场景 LOC_01｜名称`、`### 道具 PROP_01｜名称` 或 `### 线索 CLUE_01｜名称`，下一字段只能是 `#### 图片提示词` 和完整的 `text` 块。代码全文件唯一，同类型名称不重复。角色提示词写 16:9 白底四视图，场景写 16:9 单张全景；道具/线索写可生成的单主体基准图。未用的资产不输出。
2. 每集写 `## 剧集 E01｜标题`，紧接 `### 小说原文` 的 `text` 块。这里是分配给该集的小说**逐字原文**，不是改编剧本、剧情概要或审稿说明。按源文件对照，保存文字与段落顺序；完整小说覆盖与跨集重复由 agent 检查。若原文中的代码围栏会冲突，改用模板解析器支持的另一种 `~~~text`/`` ```text `` 围栏，不能改写小说正文。
3. 每条生成视频片段写 `### 片段 SH01｜30秒｜标题`；片段代码在本集唯一。只写实际使用的 `角色：CHAR_01,CHAR_02`、`场景：LOC_01`、`道具：PROP_01`、`线索：CLUE_01` 绑定行，绑定必须引用同类型已定义资产。每片段至多一个场景；跨场事件在片段边界分开。
4. 每片段必有 `#### 视频提示词` 的 `text` 块。可选 `#### 静帧提示词`、`#### 首帧提示词`、`#### 尾帧提示词`；确实不用时整个字段删掉。视频提示词保持项目的**四段结构** `【参考】`、`【公共总规范】`、`【时间轴】`、`【收尾】`（顺序固定、各出现一次）和每镜单独时间行，默认 30 秒、6–11 镜、5–10 次硬切、正文按档不超过 2000（第一档紧凑）/3000（第二档默认）Unicode 字符（含标点、空格与换行；以项目策略 `video.prompt_quality_tiers` 为准）。**不写 `【参数】` 段**：剧集/片段代码与时长已在片段标题和应用设置中，画幅、清晰度、有声/无声由应用生成设置承载，画风并入 `【公共总规范】`；正文再出现 `【参数】` 机检判不合格。镜头时间采用整数秒 `起秒-止秒秒`，从 0 连续到 30，不得有小数、空档或重叠。**提交给视频模型的时间行必须是自然语言整句：`起秒-止秒秒，内容。`**——不写镜头项目编号（`E01-SH01-S01` 这类 ID 只存在于内部 04 逐镜表用于追溯，不进正文），不用 `｜镜头…｜起始/硬切｜` 竖线字段。第一条时间行直接写开场画面；其后每行在时间码后以「硬切，」引出新镜头（如 `3-6秒，硬切，五人围成松散半圆立在车头前……`），非首行时间行的数量就是硬切次数（默认 5–10），一行一个镜头。内容先说观众看到的画面、人物动作与情绪，再把景别、机位、运镜融进句子，禁止「大全景→远景横向缓摇」这类「景别→运镜」箭头缩写，也禁止「中景以侧45°固定机位拍下」「特写从俯视45°缓缓推近」这种参数单式开场和名词堆叠。`【参考】`写绑定资产的代码与外观/空间职责（如 `CHAR_01=阿泽主外观与服装锁定；LOC_01=成都318零公里清晨起点路段`），不写上传图片编号。

   自然语言改写对照（前三个分隔字段不变，只改内容）：

   | 不合规（程序性） | 合规（自然语言） |
   |---|---|
   | 中景以侧45°固定机位拍下，五人围在车头前 | 镜头放在人群侧前方约45度的位置不动，画面取到五人膝盖以上，他们松散围在车头前，目光都落在包裹上 |
   | 特写从俯视45°缓缓推近，古图铺开 | 镜头从正上方向前俯看，慢慢凑近车头盖，泛黄古图在盖面上完全铺开，纸缘起毛、折痕清晰 |
   | 大全景用低机位跟车，越野车驶离 | 镜头压到很低的位置跟着越野车前行，看着它缓缓驶离零公里路牌，车尾碾过薄雾 |

   同一原则适用于 `【公共总规范】`、`【收尾】` 与固定资产图片提示词：优先完整句描述画面事实，减少编号、斜杠清单和参数堆叠（16:9、四视图、全景等版式硬要求保留原写法）。

   台词要写清声音出处：含对白的行必须同时写出下面的来源标签和「口型」字样，同一句跨镜或跨片段时标明画内/画外与续接规则。

   | 标签 | 含义与口型规则 |
   |---|---|
   | 口型对白 | 画面内人物开口说话，口型同步 |
   | 心理独白 | 角色内心声音，画面内但无口型 |
   | 画外旁白 | 全知旁白，无人格唇动、无口型 |
   | 画外余音 | 收束段余韵旁白，无口型 |
   | 画外延续 | 跨镜/跨片段 L-cut 延续，口型按接续镜规则 |
   | 低声自语 | 可闻不可辨的低语，无清晰口型 |
   | 混叠人声 | 多人声叠加（如反派真身），无单一唇动 |

   台词文本逐字不改；来源、口型与画面内/外状态必须可判定，不能只写「说」或孤立的引号。台词一律用直引号 `"…"`；术语、强调与专名用 `「」`，便于机检区分台词行与普通引文。含台词的镜头行还要经得起语速检查：按「汉字字数 ÷ 镜内时长」计算（标点不计），默认不超过 5.0 字/秒；旁白、无口型、混叠人声或跨镜合成句可放宽，但必须在该行写明申报，跨镜一整句按合计时长算综合速率。

   **声线锁定**：脸靠参考图锁定，声音没有同等绑定物，因此每条含人声音频的片段，【公共总规范】必须有一行以 `声线锁定：` 开头的句子，逐字取自内部声线母版（见[声线母版与配音规范](voice-and-dubbing.md)），只列本条实际发声的角色；如 `声线锁定：CHAR_01 阿泽＝26岁男声，中低、低沉克制略带沙哑；CHAR_05 小林＝22岁男声，清亮偏急。` 母版一处修改，全量重派生，禁止在单条里临时改音色。旁白/余音用全剧唯一旁白声，混叠人声按母版的叠加定义。精简 MD 不携带音频文件；TTS voice ID、配音演员或用户提供的人声样本是应用侧/后期侧资产，只登记在项目输入单与执行账，不写进 MD，也不预写不存在的音频编号。机检对「含台词但公共层无声线锁定」「锁定行缺说话角色」判错。

5. **上下文衔接是写每一行时的硬要求，不是导出后才补的检查。** 编译每个镜头行前先确认它从什么状态接进来、收在什么状态：人物的站位、坐姿、朝向、视线与手上动作与上一镜出口一致；场景地标、左右关系、光源和时间延续同一场空间；关键道具的位置、持有人、开合状态沿用上镜结果；动作动量、情绪与台词话头接得上，不跳情绪、不跳因果。`【收尾】`必须写清本片段结尾的人物位置与状态、道具去向、场景时间，并点明与下一片段第一镜的衔接方式（例：「五人已在车内各归其位、古图收入阿泽内袋，车行驶在雾路；下一片段由车内后视镜戏承接，车头方向不变」）；集与集之间同样逐对核对。衔接状态有变动时必须给出镜内可见的动作来源，不能靠硬切暗换人物位置、道具或情绪。

内部 ID 映射：`@CH-001→CHAR_01`、`@SC-001→LOC_01`、`@PROP-001→PROP_01`，剧情线索另立 `CLUE_01`；`EP01-C001→E01/SH01`。同一角色的换装属于同一角色资产的连续性设计，避免把一个人拆成多个同名角色；模板不设服装版本的独立结构字段，复杂换装须在资产提示词与片段正文中明确版本和时间。片段内可用角色、道具、线索多项绑定。

## 表演层写法边界

镜头行里的表演描写按[微表情表演层](micro-expression-layer.md)：写可见生理线索（眼睑、视线、眉心、唇线、下颌、喉结、呼吸、手部）而非抽象情绪词；每镜 1–2 个线索、每片段≤4 个、表演镜≤2 个；非笑点剧情不用会诱发微笑的模糊嘴角词，需否定时显式写「嘴角不上扬，不出现微笑」；【公共总规范】不写通用情绪形容词。表演层不得挤占剧情、台词与切镜。

## 参考图与应用边界

此 MD 仅导入**图片提示词**和绑定关系，不携带实际资产图片。导入后应用中的资产基准图仍需生成或人工上传、检查并批准；在此之前不能声称视频已有真实参考图。视频正文不要预写虚构的 `@Image 1`/`@图片1` 上传编号。应用在已有批准图片时可于视频提交阶段编译真实图片绑定，届时核对最终提交正文、图片顺序和接口长度。

四视图资产板只用于**图片资产与设定存档**；视频参考图另出单张、场景内、3/4 侧身、同套剧情服化、方向光、可见皮肤纹理、画面无文字的电影剧照。把白底四视图挂进视频参考会把正面、并排、棚光、礼服、磨皮带进成片，见 [WAN30-01](failure-cases.md#wan30-01)。

该精简导入不会读取内部完整剧本、空间卡、分镜表、评审表或成片 QC，也不会因 MD 导入而自动建立这些结构。当前可见的本地导入实现把每集 `小说原文` 存为原文、每条 `视频提示词` 存为片段文本，并把片段设为直接视频模式；跨片段连续性关系和帧计划不会由此自动建立。需要这些结构在目标应用里可编辑或自动推进时，要在导入后由该应用继续生成，或改用其完整制作包接口。若导入到已有项目，同名同类型资产可能复用原有基准提示词，以应用预览的复用提示为准。导入文件里的 `30秒` 是计划时长；生成入口实际允许的时长、模型、画幅、清晰度由应用设置和供应商能力决定。若生成入口把 30 秒拆为多段，要重新核对逐段提示词和跨段承接，不能把全 30 秒正文原样重复提交给各段。

覆盖率脚本验证各集 `小说原文` 块对用户原始小说的逐字命中（默认 ≥0.99）与源覆盖（默认 ≥0.95）；只制作部分章节时用 `--allow-partial` 并在输入单注明范围；列出的每处差异由 agent 判定授权改编还是漏改，拿不到源文件时标「待核」，不得标评审通过。

脚本检查导入结构、资产代码和绑定、每条时长、提示词字符数、时间轴、硬切、**四段结构（不得出现 `【参数】`）**、**镜头行是否自然语言成句（禁止「→」箭头缩写与「中景以侧45°固定机位拍下」式程序性写法）**、**含台词的行是否带声音来源标签与口型说明**、**含人声音频的片段是否在公共层带「声线锁定：」且覆盖说话角色**及当前目标应用的 32 MiB 请求大小上限；agent 再做一次对抗性独立评审（五视角、带证据、全量不抽样），逐条审原文覆盖、角色场景设计、表演/武打质量、**镜头/片段/集之间的上下文衔接**、声线与相邻片段状态；回滚重生后重做全量复验。脚本成功只说明本地格式与项目硬规则通过，真正导入前仍以应用预览结果为准；项目保存后的体积也可能受应用限制。若要实际写入目标项目，应由用户在应用预览后确认导入；本工作流交付 MD 不替用户执行导入。
