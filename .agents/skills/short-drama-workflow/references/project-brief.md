# 项目输入单

## 用户需要提供

1. 可读取的完整小说，或明确指定要制作的章节范围。
2. 想要的短剧风格与画风：例如现实都市、古装悬疑、写实摄影、美型 CG、二维动画；有参考作品或图片可一并给出。

### 小说源文件固定字段（必填，阶段 5 覆盖率机检从这里取基准）

| 字段 | 内容 |
|---|---|
| 源文件绝对路径 | txt/md/docx 均可；docx 由覆盖率脚本直读；微信附件等易失路径必须复制一份到 `内部/源小说_*` |
| 版本标识 | 文件名/日期/「用户原版」或「深化版」等；深化改编稿不得作为逐字覆盖基准 |
| 文件哈希 | 登记 SHA-256（`shasum -a 256`），基准被替换时必须重跑覆盖率 |
| 覆盖范围 | 全书 / 指定章节；非全书必须注明，阶段 5 用 `--allow-partial` |
| 授权改编登记 | 源文与原文块允许不同的每一处：位置、原文、改文、理由、批准人；无登记差异即判漏改 |

仅有这两项也能启动全流程。**体裁路线**是唯一需要反问的项（问法与默认值见[剧本体裁路线与评估基准](script-route-and-rubric.md)），其余缺省项一律由系统推算。不要让用户预先报集数、总时长、角色脸、服装、场景图、道具图、站位平面图；这些是工作流的推算与制作任务。片段时长先按本项目 30 秒默认值规划；未提及的改编忠实度、发行画幅、清晰度和声音策略由系统提出带理由的项目方案，用户已有要求优先。开始实际模型生成前按当前工具确认能否支持选定参数。

## 工作流自行建立的项目决策表

| 决策 | 依据与记录 |
|---|---|
| 原文覆盖 | 文件版本、章节数、已读/待读范围、关键事件出处；不得把片段输入声称为全书 |
| 改编模式 | 小说核心人设、关系、情节与用户风格；未要求重构时优先忠实 |
| 体裁路线 | 按[剧本体裁路线与评估基准](script-route-and-rubric.md)选择：R-AI（AI短剧制式，默认）/ R-SERIES（系列季结构）/ R-MICRO（微电影）/ R-PLAIN（纯 S15）；依据＝用户指定，未指定时按规则反问一次，默认 R-AI 不阻塞 |
| 评估基准 | 通用层（恒定）+ 本路线层检查项与出处；写入本单后随阶段交接与评审交接包传递，评审员不得自选尺子 |
| 全剧规模 | 剧情节拍与对白/动作/表演时长推算，初版区间与剧本后修订 |
| 集数与集长 | 自然冲突单元、每集转折和钩子，汇总每集估时与全剧总时长 |
| 视频片段 | 默认每条 30 秒，6–11 镜/5–10 次硬切；按节拍推算数量、边界和每条入口/出口 |
| 目标生成模型轨 | seedance25（默认）/ wan30 / h3（MiniMax H3，官方结构化正文）；用户点名即登记，H3 轨片段时长改为 4–15 秒并按 [W17](../../zhifeiji-workflow-router/references/workflows.md#w17) 处理；影响机检参数 `--model` 与 `--tier` |
| 画幅与清晰度 | 依据用户画风、播出方式、构图与可用工具选择；明确 16:9 或 9:16 |
| 资产设计 | 角色脸/体态/服装版本、场景地标/出入口/光源、道具与线索外观、空间平面关系；在单 MD 中交付图片提示词，实际图片待导入后生成 |
| 声音与表演 | 语言、声线提案、台词节奏、情绪强度、武打风格；未知项标创作选择 |
| 声线与配音 | 按[声线母版与配音规范](voice-and-dubbing.md)建立每角色 3–5 锚点的声线母版与角色间反差；登记人声样本（有无/路径/授权）、路线（模型直出/TTS voice ID/配音演员）、旁白与混叠人声定义；声源冻结版本 |

## 可复制的调用方式

使用 $short-drama-workflow。小说文件是「绝对路径或附件」；希望拍成「题材/叙事气质」，画风是「写实/CG/二维/其他」。请从小说自行推算全剧时长、集数和默认 30 秒视频片段数量，在内部完成逐集剧本、资产设计和分镜，最终只交付一个符合已保存精简制作包导入模板的 Markdown，包含逐字小说原文、角色/场景/道具/线索图片提示词，以及不超过 3000 字符（第二档默认；第一档 2000、第三档 4500）的逐片段视频提示词；角色声线在资产阶段定母版、每条含人声提示词公共层带声线锁定。每条默认安排 5–10 次硬切；剧情、资产、分镜和提示词在写作时即使用各阶段质量标准并在交接前评价，每批导出后脚本机检与 agent 独立复核，整改后交付。

用户已有确认素材、必须保留的台词/结局或规格时，在同一请求中补充即可；不需要为填写表格而重复提供。
