# 反例投喂契约（用户 → 工作流）

批量提供提示词反例时，按下面的格式给出，可以少一轮追问。每条案例彼此独立，**不要把不同案例的素材混在一份提示词里**（会导致无法判断哪个偏差来自哪条输入）。

## 一、每条案例的最小信息（缺一项我会标"待补"，不猜）

| 字段 | 必填 | 说明 |
|---|---|---|
| **案例号** | ✅ | 你自己编号即可，如 `R-001`；用于回执对账 |
| **实际提交的提示词全文** | ✅ | 逐字，包括【参考】【公共总规范】【时间轴】【收尾】；**不要截断** |
| **生成参数** | ✅ | 模型与版本、时长、画幅、清晰度、是否生成声音、参考图绑定顺序与张数、生成入口（应用名）、seed（若有） |
| **实际成片** | 推荐 | 视频文件或关键帧；**没有也能处理**，但只能记"文本风险"，不能判定"模型是否遵循" |
| **你观察到的偏差** | ✅ | 一句话说清哪里不对：哪个镜头、哪个字、哪个位置、什么现象 |
| **你的期望** | ✅ | 当时希望它出什么效果 |
| **已确认的修正版**（若有） | 选填 | 改过并验证有效的写法，**最有价值**，我会直接沉淀成"改写对照" |
| **生成入口/工具** | ✅ | 同一模型在不同入口行为可能不同；Wan 轨与 Seedance 轨的结论不能混用 |

## 二、批量投喂的推荐方式

1. **一个文件夹一批**：建议 `整改输出/反例批次_YYYY-MM-DD/`，每个案例一个子目录，内含 `提示词.txt`、`成片.mp4`（或 `关键帧/*.jpg`）、`观察.md`（偏差＋期望，一两行即可）。
2. **提示词与成片同名配对**；没有成片的放 `提示词.txt` + `观察.md`。
3. **一次给 3–10 条**为宜：太少我会顺手把共性写得太宽，太多容易把不同根因混成一个"类"。
4. **同类优先连着给**：如果你已经看出这批都是"空间/机位类"或"声音类"，在 `观察.md` 里点一句，省掉我的分类时间。
5. **敏感/未授权素材**请先说明；我不会把含未授权原文的片段写进反例库正文，只保留可迁移的规则。

## 三、我收到后会做什么（每批固定五步）

1. **归类**：合并到已有类别（SPACE-01 空间/机位、SYNC-01 时间线/道具/成片偏离、PROC-0x 流程与写法、VOICE 声线、MICRO 微表情/表情漂移、GEN 通用模型行为）——同类合并成一条规则，不堆同义条目；确属新根因才开新类。
2. **分栏记录**：严格分开「已观察的偏差」「待验证的原因解释」「可执行修订」「修订后的验证状态」。没有成片/没有验证的，一律不写成"已证实是提示词缺陷"。
3. **接线**：每条结论必须落进**实际检查点**——能机检的进 `scripts/`（并补自测正反用例），只能人判的进评审视角/严重度口径；只写进案例表而没人检查的，视为未完成。
4. **回写规范**：必要时同步 `SKILL.md`／`prompt-review.md`／`compact-import.md`／`rule-map.md`／`policy.json`（改默认值升版本号），并按规则传播登记表逐项核对，避免出现"改了 A 漏了 B"。
5. **回执**：给你一张对照表——案例号 → 归入类别 → 提炼的规则 → 落在哪个检查点 → 是否需要你补材料 → 是否已生成验证任务（不擅自启动生成）。

## 四、边界（我会守的）

- 一次生成错误**不等于**提示词缺陷；输入含糊、有参考图、有详细约束都不代表模型会遵循。
- 不把单个案例的具体配置（座位数、焦段、左右舵、题材）固化成所有项目的默认值。
- 新规则要用失败样例**和邻近的合理样例**双向复核，避免误伤正常反打、自然遮挡、画外角色。
- 你已锁定的人物、座位、对白、节奏、媒介不动；需要改方案时说明原因。
- 复盘本身**不启动重新生成**；只有你授权才生成。

## 五、现在就能用的最小格式（懒得整理时）

```
案例号：R-003
模型/入口：Seedance 2.5 / 即梦，30秒，16:9，720p，有声，参考图3张
提示词：<全文>
成片：有（/路径/成片.mp4）/ 无
偏差：第2个镜头，车里方向盘跑到了副驾
期望：方向盘始终在驾驶位
修正版：无 / <改后这段>
```

按这个格式给，我就能直接开工，不需要再问。
