# Wan3.0 按任务编写与编辑（v1.1，2026-10-30）

本模块在写正文前判定任务，避免把生成新故事、修订提示词、修改视频与延长视频混为一件事。先读 [官方依据与规则分层](wan30-official-rules.md)，再选本页一个分支；不复制所有模板到输出。

## 先选交付形态与任务

内部记录：任务类型、交付形态、已知／缺失素材及用途、需要修改与保留的事实、参数来源。不把内部记录额外塞进用户只要的模型正文。

| 交付形态 | 适用情况 | 结构与检查 |
|---|---|---|
| `compact_package` | 已冻结短剧资产／分镜，交付可导入精简包 | 保留【参考】【公共总规范】【时间轴】【收尾】及项目18,000上限；走原包校验与评审 |
| `direct_prompt` | 独立生成、参考创作、编辑或延长指令，或用户要求可粘贴正文 | 官方要素按需组织；实际上传后用图／视频／音频编号；不强套四段、三锚、6–11镜或硬切带 |

这是内部编译选择，不新增制作包导入字段。用户只让修改一条提示词时，不启动小说改编全流程；修改完整项目时仍守上游冻结与受影响依赖规则。

| 任务 | 可用素材 | 重点 |
|---|---|---|
| 文生视频 | 无必需媒体 | 建立主体、空间、事件、摄影及声音；无图时不能省掉必要外观事实 |
| 首帧／首尾帧 | 实际对应帧 | 延续已存在状态，说明动态过程与终点；不能再混入普通参考类型 |
| 全能参考 | 图／视频／音频，可加合法文件或网页 | 逐份分工：身份、动作、运镜、风格、音色、节奏或内容 |
| 提示词文字修订 | 用户已有文字；可附参考 | 找冲突、缺项、错误引用与时间预算；不假装已编辑视频 |
| 视频编辑 | 实际原视频；需要时加合法参考 | 定位目标、改动范围、保留与联动变化 |
| 视频延长 | 实际原视频 | 明确方向、原片边界状态、新事件与结束状态 |

素材未上传时，只交付待绑定稿并标出具体缺项；不能虚构已上传编号。缺项只影响实际提交，不阻止有依据的文字分析和修订。

## 生成与参考

1. 一两句写主题、事件及节奏走向。不是概述整个小说，也不是罗列“高级、电影感”。
2. 指定素材职责；同一图负责身份不意味着它已成为严格首帧。多宫格作为故事板参考，不当作成片第一帧的宫格排版。
3. 逐镜写摄影、可见动作、反应与结果。制作包按已冻结时间轴编译；直接提示词按实际动作与台词安排，不用建议镜数代替估时。
4. 用真实发声者和逐字台词建立声音；音色、原话、音乐／节奏参考分清。无台词与无BGM分别说明。
5. 加需要的风格／情绪与负向。风格有造型、材质、线条、光影和空间分工；情绪有触发和变化。
6. 参数在设置中确认。数字镜头时间戳是叙事控制，不能替代输出duration、ratio、resolution配置。

已有参考锁定的外观不重复编造；无参考的文生视频则补足必要身份和空间。这两种条件不要共用制作包的省略写法（简版「身份外观遵循」或三锚都以已批准的参考图为前提）。

## 提示词文字修订

先标出问题属于哪一类：官方输入冲突、引用错配、与已锁事实不符、剧情／动作因果缺失、摄影矛盾、声音／时间冲突、重复或空泛表达。只修改对应文字及相邻承接；不默改用户锁定台词、角色、商品事实或冻结切点。

以“修订后正文＋必要变更说明”交付；用户只要正文就省略过程。文字修订不需要原视频；需要判断实际画面是否错时才说明缺视频。未见视频时不能将推断写成生成失败原因，也不能保证修订后一定消除问题。

例如“摄影机前进，同时变焦拉远，人物占比保持稳定；最后不断放大脸”应拆为两个阶段，或删除相矛盾的末句；不能只增加“精准、严格、丝滑”来掩盖冲突。

## 已有视频编辑

按“编辑对象→目标变化→时段／区域→保留事实→必要联动”组织。原视频必须确实存在并被提供给模型；提示词中的“视频1”不能代替上传。

| 修改类别 | 必须说清 | 复验重点 |
|---|---|---|
| 增／删／替换元素 | 可定位对象、目标外观、位置与出现过程 | 残留、遮挡、支撑、比例、反射和影子 |
| 环境／光色／风格 | 改时间、天气、色调、背景还是媒介 | 肤色／商品颜色、光源、接触与跨帧一致性 |
| 动作／情绪 | 哪个角色、动作链与前后状态 | 动作接触、视线与表演转折，不重置道具 |
| 台词／声音 | 谁的原声改为什么，保留音色还是语气，是否改音乐 | 逐字台词、口型、语速、其他角色声音 |
| 摄影／焦点 | 改机位、路径、焦距还是焦点，终点看见什么 | 推与变焦、升降与俯仰分别描述 |

参考写法（说明模板，不作为已绑定成品）：

```text
编辑视频N，在【可定位时段／事件】将【对象或行为】改为【目标】。
目标外观按【已提供参考】；保持【与修改不冲突的剧情、身份及运动】。
随修改同步调整【必要的接触、遮挡、影子／反射或口型】，其余内容沿用原视频。
```

“所有像素、动作和背景完全不变”不作为通用保留句。把小物换成大物、换光或更换动作时，必须允许正确的空间、光学或身体联动。不能让保留项否定本次编辑。

只改台词时，不要求重新演一遍全部剧情；只改焦点时，不强制新增人物运动。编辑并非保证局部像素不动的修复工具，生成后仍要检查附带变化。

## 视频延长

与视频编辑独立路由；延长会改变边界与时长，不能列为“无需重排的局部编辑”。

- 向后：从原末端的站位、动作、持物与声音继续，新增反应或后续事件。
- 向前：新内容最终达到原开场的状态，不把原片重写成另一个起点。
- 双向：明确原视频作为中间段，分别写前端和后端新增内容。
- 身份、服饰、场景与原片继承；身体与道具不瞬间重置。新事件与声音按真实先后组织。
- 本地内部登记原片长、计划新增长、请求duration和预计返回总长；不要把它们合并成一个“时长”。当前官方Prompt与API存在需要结合任务确认的时长说明，按实际入口核对后记录，不能从旧版例子推断。
- 原视频即使只用作参考，也计入输入总视频时长；明确输出时按当前接口检查输入加输出预算。智能时长只说明意图，不伪造精确结果。

参考写法（说明模板）：

```text
将视频N向后延长。从人物已经【边界状态】继续：
先【新增动作】，接着【反应／台词与声音】，最后到达【结束状态】。
沿用原视频的人物身份、服饰、空间与视觉风格，摄影机从原运动方向平稳接续。
```

独立延长指令允许指向原视频和前后关系。制作包中“正文只写当前片段”的禁语契约不用于拦截这类合法指令。输出后重新核对片长、接缝、声音和受影响相邻片段；确需改变冻结分镜时只重开相关部分。

## 两种交付的编译示例

以下为学习用小例，素材、台词与参数都要替换为当前任务真实事实；不把示例列为已冻结项目。

### 制作包内生成片段

保持导入四段；内容按官方要素组织。总体描述在公共层前端，镜头行按本地摄影前置，收尾不重复长约束。完整格式继续使用 [Wan适配器第8节](wan30-adapter-v1.0.md)。

```text
【参考】CHAR_01＝人物身份与默认服装基准；LOC_01＝空间与光位基准。
【公共总规范】
总体描述：当前片段围绕角色发现门外动静展开，从专注转为警觉，以看向门口收束。
画风与质感：继承项目母版；角色识别锚、声线、空间与适用约束按冻结材料派生。
【时间轴】
沿用已冻结的时间行：摄影→可见动作与反应→逐句声音→本镜结果；不在此示例编造切点。
【收尾】只写末镜已经成立的姿态、朝向、持物及情绪余态。
```

### 独立台词编辑

假设原视频已真实上传为视频1，画面中只有店员这一名说话者：

> 编辑视频1，把店员原来的台词改为：“欢迎光临，请慢慢挑选。”保留店员音色和自然语气，让口型、停顿与新台词同步，沿用人物身份、站位和原摄影节奏。

这类指令无需新写30秒、6–11镜、全员不看镜头或虚构角色塑像图。若用户没有提供原视频，应交付待绑定稿，说明尚未进行视频修改。

## 检查和返修

1. **模式与素材**：任务类型、参考用途、互斥与真实上传映射正确；缺图不能声称图锚完成。
2. **文本与事实**：用户锁定信息、台词、动作因果和空间不冲突；同一公共事实只定义一次。
3. **镜头与声音**：摄影服务信息，表演有触发与变化，台词与动作有时间。
4. **导入层**：仅compact_package运行原包校验、反例审计与当前阶段评审；direct_prompt不送入包校验器以免被本地结构误伤。
5. **真实请求层**：请求JSON与媒体时长信息齐备时运行独立请求检查器；内部资产数量不作为实际上传数。
6. **实际结果**：生成后再验画面、声音、修改命中与附带变化。提示词检查与模型遵循结论分开报告。

文本本身有问题先改文本；冻结事实本身出错才重开上游；仅实际画面偏离时才选择视频编辑或重生成。延长另算时长及接口，不作为默认最便宜修复。实际调用和消耗额度仍按用户授权执行。
