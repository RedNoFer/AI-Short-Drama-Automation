# 阶段检查单（short-drama-workflow）

本清单规定各阶段**开始前必读文件**与**完成前必须落盘的内部档案**。机检脚本只验产物格式；流程完整性以本清单与执行账为准。路径中的「作品名」指本次项目的作品目录。

## 执行方式

默认采用[多智能体隔离执行](multi-agent-execution.md)：总控（主会话）只持本清单、输入单、执行账与[规则传播登记表](rule-map.md)，按阶段向**全新子任务**派执行员；执行员的上下文只含交接包（本阶段必读路径 + 上游产物路径 + 闸口），不读后续阶段文件；评审由另一个全新子任务承担。

1. 进入任一阶段前，总控按该阶段「必读」栏组装交接包；执行员读完白名单即起笔，不得自行扩读；漏读即中止子任务、回补并重派，登记 [反例索引](failure-cases.md)。
2. 阶段完成时执行员回报阶段报告（结论/证据路径/未决问题/统计），产物落盘进「创作输出/作品名/内部/」，总控核验后在「内部/执行账.md」追加一行：`| 阶段 | 结论（通过/需修改） | 证据文件 |`。
3. **阶段出口门（硬，2026-10-22 增补；2026-10-23 升级为结构检查）**：每阶段落盘后必须跑出口门，**0 错误才可进入下一阶段**：
   ```bash
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage 2
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage 3
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage 3.5
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage 4
   # 交付前必须 all（含 3.5）
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage all
   ```
   门报告逐条列在内部/06-机检结果.txt；每条整改后重跑到 0 错误。**「本阶段缺的东西等交付后补」属流程违规**——下游阶段不得以上游落盘物缺失为前提开工，按 [PROC-05](failure-cases.md#proc-05) 登记并回补。
   **门查的是结构，不是关键字**：必登标题下必须有正文（空标题判错）、表格必须有数据行（空表格判错）、每个角色必须在角色美工账里各有一行、持物链必须有箭头链或表格行；阶段 3 还要把「视感统计：」声明值与逐镜表实算值逐项对上（`scripts/crosscheck_storyboard.py`，格式见[视感自查表格式](storyboard-selfcheck.md)）。**用空壳文档骗过门，与跳步同级处理。**
4. **最终交付前总控逐行核对执行账**；任何阶段缺失或结论为「需修改」，不得标注「规范评审通过」。交付前另跑工作流清单门：
   ```bash
   python3 .agents/skills/short-drama-workflow/scripts/validate_workflow_manifest.py 创作输出/作品名 --strict
   ```
   它核对生成轨、`01c-剧情评审.md`、`05`/`05-评审索引.md`、`06-机检结果.txt` 的 `--model`、执行账与唯一非备份包；旧项目缺 `01c`/05 索引时先回补或按 legacy 登记，不得直接写通过。**执行账每行必须附出口门的运行结果**（通过的行要能看到该阶段的 0 错误记录），只有「结论=通过」而无门记录的，视为未过门。
5. 阶段顺序不得合并；母版（视觉、声线、资产 ID）冻结前不得跨集并行，冻结后阶段 3/4/5 可按集派单并行，出入口事实由总控写死（见[多智能体派单表](multi-agent-execution.md)）。
6. 内部档案只作追溯，不进入 `精简制作包.md`。
7. **质量评审是 agent 硬职责**：阶段 2 完成后、阶段 3 开始前，由一个与执行员完全隔离的评稿子任务审**资产母版**（身份锚点/角色美工账/声线母版/持物链/空间基底，只看阶段 2 产物，不读下游），结论落盘内部/03b-资产评审.md——**缺这份记录阶段 2 出口门直接判错**；阶段 4 完成后、阶段 5 导出前，另由隔离评稿子任务做一次**对抗性全量评审**，依次走完剧情忠实与因果、表演与动作可拍性、空间与上下文衔接、声音（来源/口型/声线）、**小墨6.3视感复读**（对照 E24 原版重查固定镜头比例/连续固定/微运镜/机位配比/景别焦段景深/重锤后留白镜，不合格回阶段 3 重排）、硬规六个视角，每条结论带证据，留档在内部/05。**统计类项目（固定占比/焦段与机位种数/连续固定/连三近景）已由阶段出口门机检，评审不重复手算，只判断运镜有没有叙事职责。**「生产代理自检通过」不等于评审通过。评审发现问题回滚重生后，重做一次全量评审作为修复复验（审改动也审相邻回归）；同一处两次复验不过升级用户。评审后的任何修改都要重跑官方机检、小说覆盖率与全量复验。
8. 无法派发子任务时允许单会话降级：严格限定当前阶段读取范围，执行与评审分处两个全新上下文窗口，并在执行账注明。


## 分支与固定落盘名（2026-10-23）

- **阶段 0 必须登记生成轨**：`seedance25`｜`wan30`｜`h3`，一个项目只选一个；同时登记片段单位、字符档/是否 official H3 分段、是否建站位层。分支矩阵见[生成模型分支矩阵](model-branch-matrix.md)。

- **阶段 4 评审固定落盘** `内部/05-提示词评审与整改.md`；若按 A/B 分拆，必须有 `05-评审索引.md` 指向 05a/05b 并写结论。只看 `05` 是否存在不够，必须看结论与证据。
- **阶段 5 机检固定落盘** `内部/06-机检结果.txt`；必须含登记轨对应的校验命令与结果。`--model` 与 `00-项目输入单` 不一致的通过记录无效。
- **阶段 3 的片段形态按轨切换**：Seedance 2.5/Wan3.0 默认 30 秒、6–11 镜、5–10 切；Wan 允许 2–30 秒弹性、0.5 秒粒度；H3 默认 30 秒应用片段、0–6 切、FL2VA 默认单镜，**不额外拆成 ≤15 秒条**，只有应用只接受单条输出才用 `--h3-segments official`。阶段 3 的 6–11/5–10 不是 H3 默认。
- **阶段 4 只打开登记轨的编译器**：Seedance 2.5 用 S18 四段；Wan3.0 用 Wan 三模块；H3 用 base/Ref2VA。不得在同一片段混写三种结构。

## 需要用户输入的触发点

- 阶段 2 中：声线母版与声源路线（默认模型原生音频；如用户提供人声样本登记为应用侧资产）经用户确认后冻结；阶段 4 前：按 [参考职责写法](compact-import.md) 确认采用「纯提示词、无上传图编号」路线。
- 首批实际生成时：用多角色对白片段做样片验证（同角色跨片段音色、中文口型、声音开关），通过则声线 v1 冻结；不通过按[声线规范](voice-and-dubbing.md)降级后期配音并在执行账注明。
- 阶段 6 前：确认用户已授权实际生成或已完成生成，否则跳过并注明。
