# 阶段检查单（short-drama-workflow）

**资产引用验收硬项**：阶段 3 在逐镜表登记预期人物、声源和绑定；阶段 4 全套提示词完成后执行[角色引用闭环验收](character-reference-closure.md)，反查实际正文人物/声源→角色绑定→参考→公共名单/声线，并核对服装及持物的隐含冲突。阶段 5 只检查最终包与阶段 4 已验收版本的哈希及机械映射，不重复语义闭环评审。

本清单规定各阶段**开始前必读文件**与**完成前必须落盘的内部档案**。机检脚本检查结构、版本及可确定的事实；剧情、表演与估时合理性仍须独立评审。流程完整性以本清单与执行账为准。路径中的「作品名」指本次项目的作品目录。

## 执行方式

默认采用[多智能体隔离执行](multi-agent-execution.md)：总控（主会话）只持本清单、输入单、执行账与[规则传播登记表](rule-map.md)，按阶段向**全新子任务**派执行员；执行员的上下文只含交接包（本阶段必读路径 + 上游产物路径 + 闸口），不读后续阶段文件；评审由另一个全新子任务承担。

1. 进入任一阶段前，总控按该阶段「必读」栏组装交接包；执行员读完白名单即起笔，不得自行扩读；漏读即中止子任务、回补并重派，登记 [反例索引](failure-cases.md)。
2. 阶段完成时执行员回报阶段报告（结论/证据路径/未决问题/统计），产物落盘进「创作输出/作品名/内部/」，总控核验后在「内部/执行账.md」追加一行：`| 阶段 | 结论（通过/需修改） | 证据文件 |`。
3. **阶段出口门（硬，2026-10-22 增补；2026-10-23 升级为结构检查）**：阶段 2、3、3.5、4 落盘后必须跑对应出口门，**0 错误才可进入下游阶段**；阶段 1 凭三个交接点评审放行，3.5 的登记与评审随阶段 3 同步，阶段 3 完成后运行 3.5 门：
   ```bash
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage 2
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage 3
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage 3.5
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage 4
   # 交付前必须 all（含 3.5）
   python3 .agents/skills/short-drama-workflow/scripts/validate_stage_artifacts.py 创作输出/作品名 --stage all
   ```
   门报告逐条列在内部/06-机检结果.txt；每条整改后重跑到 0 错误。脚本同时更新 `内部/阶段门记录.json`，保存该门检查过的输入文件哈希；下游派单核对收据仍匹配当前版本。**「本阶段缺的东西等交付后补」属流程违规**——下游阶段不得以上游落盘物缺失为前提开工，按 [PROC-05](failure-cases.md#proc-05) 登记并回补。
   **门查的是结构，不是关键字**：必登标题下必须有正文（空标题判错）、表格必须有数据行（空表格判错）、每个角色必须在角色美工账里各有一行、持物链必须有箭头链或表格行；阶段 3 还要将实际逐镜片段 ID 与阶段1冻结的 02a-结构化拍摄剧本.json 完整对账（缺段、重复、计划外均阻断），并把每段「视感统计：」声明值与该段逐镜表实算值逐项对上（`scripts/crosscheck_storyboard.py`，格式见[视感自查表格式](storyboard-selfcheck.md)）。**用空壳文档骗过门，与跳步同级处理。**
4. **最终交付前总控逐行核对执行账**；任何阶段缺失或结论为「需修改」，不得标注「规范评审通过」。交付前另跑工作流清单门：
   ```bash
   python3 .agents/skills/short-drama-workflow/scripts/validate_workflow_manifest.py 创作输出/作品名 --strict
   ```
   它核对生成轨、`01c-剧情评审.md`、`05`/`05-评审索引.md`、`06-机检结果.txt` 的 `--model`、执行账与唯一非备份包；旧项目缺 `01c`/05 索引时先回补或按 legacy 登记，不得直接写通过。**执行账每行须附对应放行证据**：阶段 0 记录输入核对，阶段 1 记录三个交接点结论，阶段 2/3/3.5/4 附各自 0 错误门记录，阶段 5 附最终机检；不能要求没有脚本门的阶段伪造门记录。
5. 阶段顺序不得合并。阶段 1 三个交接点评审通过即可启动阶段 2；阶段 2 出口门回查该证据。后续阶段按上游放行条件启动；阶段 3.5 路由登记与分镜批次编写、复核同步，合并后依次跑 3、3.5 门；母版冻结后可在**同一阶段内**按集/批次并行，不能用并行绕过阶段门。阶段 4 必须等阶段 1 三个交接点评审、阶段 2 资产评审与出口门、阶段 3 所有批次独立复核与出口门、阶段 3.5 路由评审与出口门全部通过，且上游版本哈希冻结后启动。`build_handoff.py --stage 4` 会拒绝缺少有效收据、未通过评审或过期哈希的派单；不要求每批重复跑全局门。阶段 5 必须等整套提示词评审明确通过且缺陷关闭后启动。出入口事实由总控写入派单（见[多智能体派单表](multi-agent-execution.md)）。

### 阶段 4 提示词开工门

总控在阶段 4 派单前只核对前置阶段的验收证据，不重做已完成的内容评审。以下条件须全部满足，并记入执行账：

- 阶段 0 输入单字段齐全，生成轨、体裁路线、原文范围及策略版本明确；
- 阶段 1 三个剧情交接点评审均通过，剧本、片段规划和覆盖映射已冻结；
- 阶段 2 资产独立评审通过、`--stage 2` 为 0 错误，角色/场景/道具/声线/持物链和命中风险场景的空间基底已定版；
- 阶段 3 各批分镜独立复核通过、`--stage 3` 为 0 错误，动作时长、机位、站位、道具承接、镜间/段间连续性均有证据；`04c-衔接事实.json` 已填全、与冻结分镜核对通过并锁定哈希；
- 阶段 3.5 打斗路由及对应证据已纳入独立复核，`--stage 3.5` 为 0 错误；无打斗也有明确的全 C 登记；
- 没有未关闭的阻断/重要缺陷；派单记录本批依赖的上游版本哈希。

任一条件不满足，不得编写提示词；退回缺项所属阶段处理。该开工门是证据和版本核对，不是再次全文评审。
**阶段 3/4 机械环节（2026-10-25 增补，与出口门并列）**：出口门查「落盘物齐不齐、结构对不对」，下面六条查「参数与衔接有没有抄错」。总控派单与执行员落盘都按此执行，数值以脚本输出为准：

```bash
# 派单：卡与批次清单同源生成（阶段 3 或 4）
python3 .agents/skills/short-drama-workflow/scripts/build_handoff.py 创作输出/作品名 --stage 4 --batch "E01-SH01~SH02" --out 内部/派单/E01-SH01-SH02_卡.md --manifest-out 内部/派单/E01-SH01-SH02.manifest.json
# 阶段 4 起草前：从冻结逐镜表派生骨架（时间轴/参考行/镜数带机械转录）
python3 .agents/skills/short-drama-workflow/scripts/scaffold_segment.py 创作输出/作品名 --batch "E01-SH01~SH02"
# 每写完一段：段内即写即检（只查段内项）
python3 .agents/skills/short-drama-workflow/scripts/lint_segment.py 内部/派单/E01-SH01-SH02_提示词草稿.md --segment E01-SH01
# 阶段3：首次从总分镜表派生完整衔接骨架；已有04c时不得覆盖，按变更范围更新
python3 .agents/skills/short-drama-workflow/scripts/continuity_facts.py 创作输出/作品名 --init
# 填齐04c的v2入口/出口与证据后，与总分镜表交叉核对；阶段3门会强制再查
python3 .agents/skills/short-drama-workflow/scripts/continuity_facts.py 创作输出/作品名 --check --source 创作输出/作品名/内部/04-片段规划与逐镜表.md --source-kind storyboard
# 阶段4全集合并后：对同一事实核对最终提示词；阶段4门会强制执行
python3 .agents/skills/short-drama-workflow/scripts/continuity_facts.py 创作输出/作品名 --check --source 创作输出/作品名/精简制作包.md --source-kind prompt
# 并行期随时：批次台账（四状态、哈希对齐、上游失效、规范漂移）
python3 .agents/skills/short-drama-workflow/scripts/batch_ledger.py 创作输出/作品名 sync
python3 .agents/skills/short-drama-workflow/scripts/batch_ledger.py 创作输出/作品名 status
```

阶段 3 批次标「通过」必须附独立评审记录和 `0 错误` 批次门结果；阶段 4 草稿在整套提示词独立评审完成前保持「待评」。阶段 4 全覆盖评审按[评审报告与范围版本锁](multi-agent-execution.md#阶段-4-评审报告与范围版本锁)记录每段唯一的当前验收行（ID、正文 SHA-256、明确通过结论）。每批 `--review` 指向实际报告，可共享报告但不可用纯链接索引代替；分节报告只锁本批片段与共享依赖，旧平铺报告仍锁整文件。评审通过后所有阶段 4 批次登记为「通过」，`validate_stage_artifacts.py --stage 4` 核对覆盖哈希、批次状态、局部门结果和上游版本。`batch_ledger.py` 拒绝缺少明确零错误门结果、草稿已变但沿用旧评审、或所锁评审范围已变化的「通过」状态。**这些命令只保证机械字段不错**，剧情/表演/空间/声音的提示词编译质量由整套完成后的独立评审确认；`lint_segment` 通过不等于语义评审通过或交付通过。

6. 内部档案只作追溯，不进入 `精简制作包.md`。
7. **独立评审按阶段分工，不在交付末尾重复审上游**：阶段 1 在三个剧情交接点评审；阶段 2 由隔离评稿人评资产母版，结论落盘 `内部/03b-资产评审.md`；阶段 3 各分镜批次由独立评审员复核，合并后做全局交叉检查；阶段 3.5 的打斗路由与证据由同一分镜评审包核对，避免另起一轮重复派审。提示词写作期间，作者逐段自查并运行段内 lint；**整套提示词按固定模板合并为唯一 `精简制作包.md` 待评稿后先跑登记轨的包校验与原文覆盖率、清除机械硬错，再进行一轮独立全覆盖提示词评审；Wan warning按[处置契约](prompt-review.md#wan风险提醒处置)在本轮留证，阶段4严格门验证有效关闭**，按非重叠范围分工仍算一轮，结论留档 `内部/05-提示词评审与整改.md`。该评审验证提示词是否忠实、清楚地编译已通过的剧情、分镜、资产、站位、声音和分支要求，不重新判定上游创作是否成立。阶段 5 确认同一文件为最终导出版本并复跑机械校验，不再启动第二轮创意评审。统计类项目由对应阶段脚本检查，评审不重复手算。「生产代理自检通过」不等于独立评审通过。

   评审发现问题时，先判断缺陷来源：提示词新增矛盾、漏写或分支格式错误，只修对应提示词；源稿本身问题属于上游验收漏项，标记漏检原因，只重开最早出错的产物及其下游依赖，禁止把全流程从阶段 0 重跑。修复复验按影响范围定向执行：未变提示词凭内容哈希与原评审记录确认；变更提示词及相邻接口重审；受影响的共享资产/分支/阶段门重查。阶段 5 的最终机检可重复运行，但不因此重开未变内容的语义评审。同一缺陷两次复验不过，由总控定位根因并更换修复方法；只有需要改变用户锁定目标或缺少必要用户决策时才询问用户。
8. 无法派发子任务时允许单会话降级：严格限定当前阶段读取范围，执行与评审分处两个全新上下文窗口，并在执行账注明。


## 分支与固定落盘名（2026-10-23）

- **阶段 0 必须登记生成轨**：`seedance25`｜`wan30`｜`h3`，一个项目只选一个；同时登记片段单位、字符档/是否 official H3 分段、是否建站位层。分支矩阵见[生成模型分支矩阵](model-branch-matrix.md)。
- **阶段 1 三次剧情评审合并落盘** `内部/01c-剧情评审.md`；缺记录或未通过不得进阶段 2（当前由总控前置检查，脚本无 `--stage 1`）。
- **阶段 4 评审固定落盘** `内部/05-提示词评审与整改.md`；若按 A/B 分拆，必须有 `05-评审索引.md` 指向 05a/05b 并写结论。只看 `05` 是否存在不够，必须看结论与证据。
- **阶段 5 机检固定落盘** `内部/06-机检结果.txt`；必须含登记轨对应的校验命令与结果。`--model` 与 `00-项目输入单` 不一致的通过记录无效。
- **阶段 3 的片段形态按轨切换**：Seedance 2.5/Wan3.0 默认 30 秒、6–11 镜、5–10 切；Wan 允许 2–30 秒弹性、0.5 秒粒度；H3 默认 30 秒应用片段、0–6 切、FL2VA 默认单镜，**不额外拆成 ≤15 秒条**，只有应用只接受单条输出才用 `--h3-segments official`。阶段 3 的 6–11/5–10 不是 H3 默认。
- **阶段 4 只打开登记轨的编译器**：Seedance 2.5 用 S18 四段；Wan3.0 用「【参考】【公共总规范】【时间轴】【收尾】」四段；H3 用 base/Ref2VA。不得在同一片段混写三种结构。

## 需要用户输入的触发点

- 阶段 2 中：声线文字母版与声源路线（默认模型原生音频；如用户提供人声样本登记为应用侧资产）按用户已有约束标「工作流定版 vN」；仅明确要求审批或已有待决偏好时等待确认，实际试听与声源冻结留待媒体生成验收，不阻断 MD 交付；阶段 4 前：按 [参考职责写法](compact-import.md) 确认采用「纯提示词、无上传图编号」路线。
- 首批实际生成时：用多角色对白片段做样片验证（同角色跨片段音色、中文口型、声音开关），通过则声线 v1 冻结；不通过按[声线规范](voice-and-dubbing.md)降级后期配音并在执行账注明。
- 阶段 6 前：确认用户已授权实际生成或已完成生成，否则跳过并注明。
