# 商品卖点、用户台词与素材分支

## 1. 先处理用户真正要卖的内容

用户给出的产品资料、功能和体验描述属于本次创作依据，不要求所有卖点都能从静态图直接看见。记录其来源为“用户提供”，不冒充独立测试或第三方认证；遇到互相矛盾、明显不可能或关键机制不清的内容，针对冲突澄清。

区分三种输入：

| 用户输入 | 处理方式 |
|---|---|
| 提供完整台词，要求原话/逐字保留 | 保留台词及顺序，组装说话人、语气、时段、镜头和声音；超时先指出并提供精简建议，不静默改写 |
| 提供完整台词，允许润色 | 保留核心事实、语义和卖点，改成自然口语，删重复，按真实说话窗口安排 |
| 仅提供产品卖点/目标 | 主动写成针对该商品的台词，再围绕卖点设计画面；不要求用户先写台词，也不退回“给你看清外观”的默认话术 |

编写内部映射：**用户主卖点 → 对使用者的实际意义 → 一句自然口播 → 对应演示/使用场景 → 依据或缺项**。15 秒通常只承担一个核心利益，可带一个紧密相关的辅助特点；不硬凑固定句数。

例如用户给“折叠自行车、收纳方便”：可以写“骑完折起来，收纳更省地方，通勤带着也方便。”不能只说“车架、车把和轮组都看得很清楚”，也不能擅自增加“3 秒折好、塞进任何后备箱、单手提走”。用户给“耳机佩戴舒适、外形好看”：可以写“这副耳机戴起来舒服，颜色也好搭，出门随手戴上就很方便。”不能加“久戴不累、零压迫、降噪、超长续航”等未提供内容。示例只说明文案转换，不能作为所有商品已具备该特点的证据。

不虚构第一人称使用经历，例如“我已经戴了一整天”“用过就再也不换”；用户明确提供的真实经历可按授权表达。主观审美可用自然意见表达，功效和功能不增添量化、时效或普遍保证。

## 2. 画面要服务主卖点

| 卖点类型 | 画面设计与边界 |
|---|---|
| 折叠/伸缩、收纳省空间 | 有真实机构/操作或折叠态参考时设计抓握、解锁、运动与锁定；“可折叠”不能推定“车架可伸缩”。只有整车图时保留用户的功能介绍，展示已知结构；完整折叠演示明确待补资料，不凭空设计铰链、折叠结果或假对比 |
| 耳机佩戴方便、舒适、美观 | 可从开箱衔接到经剪辑省略佩戴的成年人物使用镜头；无模特图时将人物作为新设定，不能声称锁定真实模特。佩戴动作不插穿耳朵，不制造耳形变形；不以面部表情当作舒适度测试 |
| 面膜滋润、使用舒服 | 用展开、成人敷用或轻按服帖的镜头配合用户卖点；上脸需人物与产品状态交代。保留肤质纹理，不生成磨皮、白化、皱纹消失或即时修复对比来冒充滋润证据 |
| 唇膏色调好看、感觉滋润 | 展示膏体色调，必要时增加明确为新设计的成人试色/上唇镜头；不能从膏体颜色保证上唇完全同色。保留真实肤质，不编色号、成分、持妆或修复效果 |
| 服饰舒适、美观 | 展示实际穿着、自然转身、衣料随动作变化和搭配效果；舒适是用户提供的主张，不推断面料成分、弹性、抗皱或保暖测试结果 |
| App 具体功能 | 先取得 App 名称、用户要讲的功能、操作与结果；涉及可辨识界面时取得真实截图/录屏或已确认页面描述。不编按钮、功能或操作结果。资料不足时只暂停 App 演示条目，不用“屏幕好看”替代；需要后期贴屏时明确说明，未绑定素材不能称为可直接生成 |

不必每个卖点都做实验；口播可以直接表达用户提供的特点。画面可以提供使用情境，但不得伪造性能证据。真实演示缺资料时，应明确当前只能完成哪一层，不把模板标为成稿。

## 3. 商品图与模特图分别判断

输入模式先按 wan30-format.md 确定，再按本表分配素材角色；某组合可用于提示词编写，不代表目标平台允许同时上传。

| 输入组合 | 提示词写法 |
|---|---|
| 无图、有产品文字资料 | 完整描述已知商品和目标人物/场景，不写“沿用图1”；未确认外形只能作为设计方案，不承诺复现真实 SKU |
| 只有商品图 | 图片锁定商品；需要人物时采用简短明确的成年人物设定，注明人物由文字设计；也可选择手部或无人展示，按卖点需要决定 |
| 商品图本身包含模特 | 该图可以同时承担商品与人物参考；明确是否沿用此人。参考生成中只绑定约定身份/服装，不自动继承背景；作为首帧则沿用现有场景与姿态 |
| 商品图＋独立模特图 | 分别标明“图N锁定商品”和“图M参考模特身份”；服饰商品由商品图决定，不让模特图原衣服覆盖商品，背景/姿态仅按任务需要引用 |
| 只有模特图＋产品文字 | 图片锁定人物；商品按已确认文字设计，真实商品外形缺失时注明，不把模特图误当商品外观证据 |
| 无模特图但需要真人 | 按任务设定成年人物及必要外观、服装，跨镜延续；不声称有脸部母版，不假设每次独立生成自动是同一人。仅手部时不强加人物身份图 |

每张图片都登记用途：商品外观、模特身份、服装、场景、起始帧或结束帧；允许一图多用，但不默认认定。参考生成与首帧约束的区别保持明确，新增使用场景使用硬切或明确的时间经过，不让商品/人物在连续镜头中瞬移。

## 4. 音频有无及用途分别判断

| 音频情况 | 处理方式 |
|---|---|
| 未传入音频 | 仍可编写完整台词与声音；用文字描述必要音色、语言和语气，不出现“音频1”或声称沿用上传声音 |
| 音色参考 | 仅绑定说话人的音色及必要表达特点；实际说什么由确认台词决定，不自动照抄样本中的广告内容 |
| 原始口播/逐字音轨 | 明确是按内容重生成，还是要保留原始音轨。精确沿用时按真实音轨时长安排画面；不承诺文字提示词能保证逐样本复制，必要时采用后期配音/口型流程 |
| 音效/环境声参考 | 指明对应材质、动作与时段，不当作人声音色，不把音轨里的声音自动写成画面事件 |
| 背景音乐参考 | 指明音乐用途和与人声的音量关系，不将音乐内的人声自动当模特台词 |
| 用途不明的音频 | 仅询问其用途，不擅自选为人声或音乐；不妨碍其他已明确部分继续写作 |

引用只使用实际传入的音频编号；图片和音频分别编号。先检查目标输入模式是否接受对应素材组合：不支持时在正文外说明应换模式或后期处理，不能保留无法绑定的音频引用并标记可执行。

## 5. 交付前检查

- 用户主卖点进入了台词吗？画面在帮助理解该卖点吗？
- 换成别的产品后台词仍可原样使用吗？若是，补上真正的品类功能、体验或使用价值。
- 用户给的是原话还是方向？处理是否符合其授权？
- 商品图、模特图、场景图和音频引用是否各负其责？
- 台词的事实来自哪里？是否凭空增加规格、效果、经历或界面？
- 仅部分资料缺失时，是否完成其余条目，并把受影响内容标为待补而非“完整可直接生成”？
