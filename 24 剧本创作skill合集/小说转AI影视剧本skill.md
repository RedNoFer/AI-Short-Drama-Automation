# 小说转化AI影视剧本引擎 (Novel-to-Screenplay Converter)

---

## 概述

本技能将**小说原文**或**故事大纲**转化为可直接用于AI影视制作的剧本。产出格式与《南美为奴，我靠鉴定宝石逆天改命》剧本完全对齐：竖屏AI短剧制式——每集约1000字、1-3个场次、▲动作行+情绪括注台词，一集对应一支1-1.5分钟AI成片。

**集数不预设**：总集数由所给内容量自由合理安排，剧情紧凑、零注水——给多少故事，就排多少集，讲完即止。只有当使用者明确要求固定集数（如"一键出60集"）时，才进行内容填充扩充。

本技能不是"缩写小说"，而是**手术式改编**：砍支线、并人物、翻译心理为画面，保留原作爽点骨架，重塑为镜头语言。

## 触发条件

当用户的请求包含以下任意特征时，使用本技能：
- 提供小说原文/章节/完本，要求"转剧本""影视化""改成短剧"
- 提供故事大纲/梗概/剧情梗概，要求扩写为分集剧本
- 明确提到"AI影视""AI短剧""转化剧本""小说改编"
- 要求输出格式为此剧本制式（▲动作行、场次制、分集钩子）

## 输入类型与策略

| 输入类型 | 特征 | 核心策略 |
|---|---|---|
| 完本小说 | 50万-300万字 | **重度压缩**（压缩比可达30:1），大砍支线、合并配角，提取主线骨架重排节奏 |
| 中短篇/单章 | 1万-20万字 | **中度压缩**，保留主线与2-3条重要支线 |
| 故事大纲 | 几百-几千字 | **扩写**，按短剧节奏重新设计钩子和爆点分布，血肉需自造 |

先判断输入类型再动笔。

### 集数估算原则（内容量决定集数，不预设、不凑数）

1. 数出内容里**不可省略的主线事件/爽点**，每个事件对应1-2集
2. 集数 = 主线事件数 × 事件间钩子衔接所需的过渡集，**宁可少排不注水**
3. 参考量级（仅作参考，非默认值）：一个完整长篇故事的骨架通常自然落在20-60集；一个中等体量的故事可能只有10-25集；一个短纲可能只值5-15集——都对
4. 拿不准时向用户报出估算值和依据（"主线共X个大事件，建议X集"），由用户确认

## 核心创作哲学

### 一句话概括
**小说让读者"读进去"，剧本让AI"拍出来"——每句话都必须能变成一个画面或一段声音。**

### 九条铁律
1. **一切心理活动必须有出口**：小说里的心理描写 → 转为VO（内心独白）、或删掉、或转化为可见动作（攥拳、咬牙、瞳孔骤缩）
2. **一个▲行 = 一个可生成的画面**：AI视频生成的最小单位是镜头，每个▲行必须是一个独立的视觉动作，严禁多个动作挤在一行
3. **每集必须以钩子收尾**：悬念、反转、危机、身份揭露，四选一。观众划走的那一秒就发生在集尾
4. **爽点密度不降级**：原著每3-5章一个爽点，剧本必须每集至少一个（打脸/升级/反转/情感推进），开局前3集必须含一次核心爽点
5. **台词口语化、短句化**：单句不超过20字为主，说人话，说快节奏的话；书面语、大段独白一律拆碎或砍掉
6. **支线宁死不留**：不能在3集内回归主线的支线全部砍掉，人物能合并就合并
7. **集数服从内容，注水零容忍**：不给内容注水凑集数，也不为省事压缩掉必要的情绪铺垫；故事讲完即落`（完）`，哪怕只有8集。若为凑集数而出现的"原地打转"剧情（重复冲突、无效对话、无功能闪回）一律删除
8. **视觉可执行性优先**：避免大规模群战场、复杂运镜、微表情特写连续堆叠；换脸/换装/转场频繁的段落重新设计
9. **忠于原著的"感觉"，不忠于原著的"过程"**：保留人设、关系、核心爽点和结局指向；过程可以为了节奏重新排列

## 剧本格式规范（铁标准，逐条执行）

### 文档总结构
```
简介：（一段话，80-150字，交代主角处境+核心金手指+主线目标）
人物小传：
（每个主要人物按以下格式）
角色名·全名 英文名（年龄）
身份：（一段话，人物来历与在故事中的位置）
性格：（一段话，行为逻辑与说话方式，必须可指导表演）
外貌：（一段话，固定视觉特征——发型/体型/标志性服装，供AI生图锁定角色资产）

第一集
1-1
地点：（场景名） 日/夜 内/外
人物：A、B、C（顿号分隔；无名群演写"劳工N、安保N"）
▲（动作行）
角色名（情绪/方式）：台词
...
（完）
```

### 行级语法
- **动作行**：`▲`开头，一句一个视觉动作，主谓宾完整。如：`▲迪伦咬着牙刚举起镐头，忽然瞳孔一缩，镐头从手里脱落`
- **台词行**：`角色名（情绪/方式）：台词`。括注从两个维度写：
  - 情绪状态：震惊、得意、冷声、暴怒、平静、自信、讥讽、威胁、坚定
  - 方式动作：低声、高声、咬牙、冷笑、轻笑、结巴、沉声
  - 组合示例：`薇拉（冰冷）：扔进河里喂鳄鱼！`
- **内心独白**：`角色名（情绪VO）：内容`。VO是竖屏短剧的叙事润滑剂，主角每集1-3次，用于交代背景、动机和爽点预感
- **画外音（人物不在画面中）**：`角色名（OS）：内容`，或`角色名（画外音）：内容`
- **群演命名**：有功能无名字的角色按 `职业+字母/N` 命名：劳工A、安保N、宾客B

### 特殊叙事标记
- `【闪回】` … `【闪出】`：成对使用，包裹闪回段落
- `【闪回X-Y】`：闪回到第X集第Y场时标注场次编号，供制作时复用素材
- `【字幕：角色名——身份】`：角色首次登场标注，如`【字幕：贾斯珀——迪伦的朋友】`
- `【快切】`：快速剪辑蒙太奇段落
- `【黑屏切一下】`：时间跳跃/强转场
- `【视频画面】`：画面中出现的屏幕内容（监控、手机等）

### 场次与集结构
- 场次编号：`集数-场次序号`，如`2-1`、`2-2`，每集重新计数
- 场景头三行固定：场次号 → 地点/时间/内外 → 人物列表
- 单集标准体量：**900-1200字、1-3场、20-30个▲行、15-20条台词**（±20%浮动）
- 全剧最后一集结尾标注`（完）`

## 创作工作流

### 阶段0：输入评估与规格确认

1. **判断输入类型**（完本/中短篇/大纲），按"集数估算原则"数出主线事件数，得出建议集数
2. **确认规格**（拿不准就问，别猜）：
   - 总集数：报出建议值+依据（"主线共X个大事件，建议约X集"）；**不预设上下限，用户不要求就不填充**
   - 单集体量：默认按标准制式（约1000字/集）
   - 是否忠于原著结局；有无必须保留/必须删除的内容
3. **提取主线骨架**：一句话说清主角的处境→金手指→目标→最终对决对象

### 阶段1：改编手术（在脑内完成，只呈现结论）

对原著执行四刀：
1. **砍支线**：与主线无关或3集内不能回归的支线全部删除
2. **并人物**：功能重叠的配角合并（两个损友并成一个、两个对手并成一个）；无名有戏的群演保留字母命名
3. **排爽点**：把原著爽点按集分配，确保每集至少一个，前3集必有核心爽点
4. **设计钩子链**：每集结尾的钩子必须在下一集前30秒内兑现或升级

### 阶段2：输出《剧集架构》——先给用户确认，再写正文

输出包含：
1. **简介**（80-150字）
2. **人物小传**（完整格式，主角+对手+重要配角，一般5-8人）
3. **分集梗概表**：每集一行——`集数 | 核心事件 | 爽点 | 结尾钩子`
4. **结构标注**：三幕分界（开端-对抗-清算），中点大反转位置，最低点位置

**获得用户确认后才进入阶段3。** 若用户直接说"开始写"或提供了明确规格，可将阶段2与首批正文合并输出。

### 阶段3：正文转化（分批输出）

- 每批5-8集，写完一批停下等用户反馈（节奏对不对、人物味道对不对），再写下一批
- 严格按格式规范逐行执行
- 单批输出量不超过10集，防止质量滑坡

### 阶段4：收尾

- 最后一集完成后标注`（完）`
- 自查格式清单（见下），发现问题当场修正再交付

## 转化对照表（小说写法 → 剧本写法）

| 小说原文写法 | 剧本转化 |
|---|---|
| 大段心理描写 | VO（1-2句提炼）或可见动作 |
| 环境描写 | 1-2个▲行（只留有叙事功能的细节） |
| "他想起了三个月前的往事" | 【闪回】…【闪出】 |
| 转场/时间跳跃 | 【黑屏切一下】或直接切场次 |
| 对话中的大段陈述 | 拆成短句对话，加质问/反应 |
| 角色介绍段落 | 【字幕：角色名——身份】 |
| 战斗/打斗 | ▲行拆解为一拍一个动作，节奏短促 |
| 视角切换/旁白议论 | 删除，或并入主角VO |

## 质检清单（每批交付前过一遍）

- [ ] 每集是否以钩子收尾？钩子强度够不够让用户点开下一集？
- [ ] 每集是否有至少一个爽点/情绪爆点？
- [ ] 是否存在注水？（原地打转的重复冲突、无功能对话、无叙事作用的闪回——有则整段删）
- [ ] 是否存在一个▲行塞了两个以上动作？（有则拆行）
- [ ] 是否存在书面语台词、超过20字的长台词？（有则拆碎）
- [ ] 心理描写是否有漏网之鱼未转VO/动作？
- [ ] 场景头三行是否完整（场次号/地点时间内外/人物）？
- [ ] 人物名、地点名前后是否一致？（转剧本中途改名是事故）
- [ ] 闪回是否成对标注【闪回】【闪出】？
- [ ] 视觉上是否存在AI难以生成的元素（复杂群像、频繁换装、精确微表情）？
- [ ] 单集体量是否在900-1200字区间？

## 特殊情况处理

- **用户要求固定集数**（如"一键出60集"而内容只够30集）：此时才做内容填充，且填充必须"有戏"不注水。填充优先级从高到低：
  1. 加**对手博弈回合**：给主要对手增加1-2轮攻防（设局→反制→反杀），每轮仍要爽点+钩子
  2. 加**中段新危机**：在原有事件之间插入与主线咬合的新冲突（新对手、旧仇回流、金手指代价显现）
  3. 加**单元事件**：主角用金手指解决独立小事件（救人/鉴宝/立威），单集成环且埋主线伏笔
  4. 加**感情线/关系节点**：主要人物间的试探、结盟、决裂，每次推进必须改变关系状态
  - 填充量仍不够时，如实告知用户内容承载力上限，宁缺毋滥
- **原著节奏拖沓**：允许把原著3章压缩成1集；反过来，关键大高潮（如最终对决）可扩为1集只写一个场景
- **原著有雷点**（审核风险内容）：改编时直接净化处理，不改格式不提示
- **大纲输入信息不足**：人物性格、关系、金手指规则等按短剧惯例自造，在《剧集架构》中标注"（自造，可调）"
- **用户提供了人物资产/角色形象参考**：小传外貌描述与用户资产对齐，避免与已有角色形象冲突
